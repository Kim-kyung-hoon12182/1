## 1. 무엇을 했는가

1. **설문 분석:** 24명 응답을 분석했다. 처음 생각한 "맡길 일 찾기"나 "자동 실행"보다 "결과를 확인하고 고치는 시간"(12명)과 "결과를 믿기 어렵다"(10명)가 훨씬 많이 나왔다.
2. **방향 수정:** 대상을 AI 초보에서 "매주 같은 문서를 AI로 쓰는 사람"으로 바꿨다. 핵심 기능도 자동화에서 "결과마다 확인할 곳 짚어주기"로 옮겼다.
3. **데스크 리서치:** 세 번에 나눠 공개 조사, 비슷한 서비스, 사용자 글을 찾았다. 처음 생각한 차별점("고친 게 다음에 남는다")은 ChatGPT·Claude 메모리에 이미 있다는 걸 알고 다시 세웠다.
4. **PRD 작성:** 배경 → 문제 → 1~3차 가설 → 기능 → 검증 지표 순서로 썼다. 근거가 부족한 것은 따로 모았다.
5. **개발 세팅:** 비용을 쓰지 않도록 Gemini 무료 API로 앱 뼈대를 만들었다.

## 2. 네 가지 개념 정리

참고: [Pretotyping: a way to test product-market fit very quickly](https://medium.com/uwaterloo-voice/pretotyping-a-way-to-test-product-market-fit-very-quickly-334db5667830)

| 구분 | 확인하는 질문 | 누구에게 | 만드는 것 | 예시 |
| --- | --- | --- | --- | --- |
| 프리토타입 | 이거 사려나? (올바른 것을 만들고 있나) | 실제 고객 | 가짜에 가까운 최소한의 것 | 랜딩페이지 사전 가입 |
| 프로토타입 | 만들 수 있나? 쓸 수 있나? (올바르게 만들고 있나) | 내부, 소수 테스트 사용자 | 작동하는 초기 버전, 디자인 목업 | 기술·사용성 테스트 |
| MVP | 핵심 가치만으로 쓰일까? | 실제 사용자 | 핵심 기능만 돌아가는 최소 제품 | 수작업이 섞인 첫 출시 |
| PMF | 시장에 안착했나? | 시장 전체 | 계속 다듬고 키우는 제품 | 재방문, 입소문, 확장 |

### 2-1. 프리토타입

- **언제:** 아이디어가 맞는지 불확실할 때
- **초점:** 내가 올바른 것을 만들고 있는가
- **핵심:** 만들기 전에 사람들이 실제로 행동하는지 본다. "써볼래요?"라는 말보다 가입, 클릭 같은 행동이 더 정확한 신호다.

| 방법 | 내용 |
| --- | --- |
| 소개 페이지 + 사전 가입 | 제품 소개 페이지를 만들고 사전 가입자 수를 측정 |
| 가짜 버튼 | 아직 없는 기능의 버튼을 일부러 노출하고 클릭률을 측정 |
| 뒤에서 수동 처리 | 자동처럼 보이지만 실제로는 사람이 뒤에서 처리 |

### 2-2. 프로토타입

- **언제:** 만들 가치는 어느 정도 확인됐고, 기술과 사용성을 확인해야 할 때
- **초점:** 내가 올바르게 만들고 있는가
- 실제로 작동하는 초기 버전이나 목업으로, 주로 내부나 소수 사용자에게 테스트한다.

### 2-3. MVP

- 완벽한 제품이 아니라 **핵심 가치만 돌아가는 최소 제품**을 실제 사용자에게 내놓는다.
- 프로토타입과의 차이는 결국 **내부 확인용이냐, 고객에게 내놓는 것이냐**다.
- 핵심 가치만 확실하면 일부는 수작업이어도 된다.

### 2-4. PMF (Product-Market Fit)

맛집으로 비유하면 이렇다.

| 단계 | 상태 | 집중할 것 |
| --- | --- | --- |
| Pre-PMF | 아직 맛집이 되기 전 | 어떻게 하면 손님 입맛에 맞는 음식을 만들까 |
| Post-PMF | 손님이 알아서 다시 찾아옴 | 재방문 유지, 손님 확장, 직원 늘리기 |

### 2-5. 한 줄씩

- **프리토타입:** "이거 사려나?" → 가짜로 수요 확인 (사전 예약)
- **프로토타입:** "만들 수 있나?" → 내부 작동 테스트 (디자인 목업)
- **MVP:** "핵심만 판다!" → 실제 출시와 피드백 (수작업, 최소 기능)
- **PMF:** "주문 폭발!" → 시장 안착과 성장 (마케팅, 투자 시점)

## 3. 내 프로젝트에 대입해보기

**지금 위치는 Pre-PMF다.** 문제가 있다는 건 설문과 공개 조사로 확인했지만, 내 해결책이 통하는지는 아직 모른다.

| 확인할 것 | 해당 개념 | 이번 프로젝트에서 할 일 |
| --- | --- | --- |
| 결과마다 근거를 표시하는 게 기술적으로 되나 | 프로토타입 | 예시 재료 10개로 Gemini가 돌려준 근거 문장이 재료와 맞는지 대조 성공률 확인 |
| 근거 표시와 기준 누적이 실제로 확인·수정을 줄이나 | MVP | 1~2차 기능을 실제로 작동하게 만들어 엑스포에서 사용 |
| 자동화까지 원하나 | 프리토타입 | 실제 자동 실행은 만들지 않고, 맡기기 제안 카드에 "예약 작업에 바로 연결" 버튼을 두어 클릭률 측정 (누르면 "준비 중이에요"와 관심 등록) |

**설문에도 한계가 있었다.** 설문 마지막에 아이디어를 보여주고 반응을 물었는데, 이건 "써볼래요?"라는 말에 대한 답이다. 프리토타입 관점에서 보면 말보다 행동이 더 정확하다. 엑스포에서 버튼 클릭이나 다시 쓰겠다는 등록 같은 행동 데이터를 받으면 설문보다 강한 근거가 된다.

**자동화는 프리토타입으로 확인하는 게 맞다.** ChatGPT 예약 작업은 외부 연동 API가 없어서 지금 만들기도 어렵다. 그렇다고 빼버리면 3단계 수요를 확인할 방법이 없다. 버튼만 노출해서 몇 명이 누르는지 보면, 만들지 않고도 다음 단계로 갈지 판단할 수 있다.

## 4. 오늘 배운 것

1. **네 개념은 만드는 물건이 아니라 질문으로 구분한다.** "이거 사려나?", "만들 수 있나?", "핵심만으로 쓰일까?", "시장에 안착했나?"
2. **말보다 행동이 정확한 신호다.** 설문의 "써보고 싶다"보다 실제 클릭과 가입이 더 믿을 만하다.
3. **한 제품 안에서도 기능마다 단계가 다를 수 있다.** 근거 표시는 MVP로 만들고, 자동화는 프리토타입으로 수요만 확인할 수 있다.
4. **데이터를 보고 방향을 바꾸는 건 실패가 아니다.** 처음 생각한 "맡길 일 찾기"는 3명, "확인·수정 시간"은 12명이었다. 처음 아이디어를 고집했으면 엉뚱한 걸 만들었을 것이다.
