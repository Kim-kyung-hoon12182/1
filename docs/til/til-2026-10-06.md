안녕하세요. 김경훈입니다.
오늘은 0 to 1 메이커톤에서 혼자 만들 제품의 주제를 정했습니다. 아이디어를 많이 냈지만 대부분 "이미 있는 서비스"에 막혔고, 마지막에는 **반복되는 업무를 AI가 알아서 대신 만들어두는 서비스**로 방향을 정했습니다.

## 1. 무엇을 했는가

1. **후보 탐색:** 취업 지원 관리, 저장한 콘텐츠 정리, 팀 프로젝트 회의, 템플릿 재사용 등 여러 후보를 봤지만, 직접 겪어보지 않아 공감이 안 되거나 이미 비슷한 서비스가 있어서 내려놓았다.
2. **내 아이디어로 돌아오기:** 처음부터 마음에 있던 "AI로 일을 줄이고 싶은데 잘 못 쓰는 사람을 돕는 것"을 다시 꺼냈다.
3. **데스크 리서치:** 공개 통계와 비슷한 서비스를 찾아 필요한 문제인지, 해볼 만한지 확인했다.
4. **방향 확정:** 만들기 쉬운 쪽과 시장성이 있는 쪽을 비교한 뒤, 시장성 쪽으로 정했다.

## 3. 왜 이 방향으로 정했는가

처음에는 "오늘 한 일을 고르면 AI에 맡길 일을 짚어주는 것"이 하루면 만들 수 있고 근거도 충분해서 좋아 보였습니다. 그런데 시장성과 지금 해야 하는 이유로 다시 보니 약점이 보였습니다.

| | AI 어디에 쓸지 짚어주기 | 반복 업무를 AI가 대신 만들어두기 |
| --- | --- | --- |
| 쓰는 빈도 | 한 번 알고 나면 다시 안 옴 | 매주 반복해서 씀 |
| 시장 흐름 | AI 사용자가 빠르게 늘어 대상이 줄어듦 | 보고 문화는 AI가 퍼져도 남음 |
| 인터뷰 | 비IT 지인이 없어 확인 어려움 | 보고서 써본 사람이면 누구나 대상 |
| 만들기 | 하루, AI 연결 없음 | 이틀, API 키 결제 필요 |

만들기 쉬운 것을 기준으로 하면 왼쪽이, 시장성을 기준으로 하면 오른쪽이 낫습니다. 오늘 추천이 몇 번 바뀐 것도 결국 **기준을 먼저 정하지 않고 아이디어부터 비교했기 때문**이었습니다.

## 4. 기술적으로 알게 된 것

- **웹사이트는 사용자가 다른 프로그램에서 뭘 하는지 볼 수 없다.** 백그라운드로 업무를 지켜보려면 PC 프로그램이나 크롬 확장이 필요하다.
- **스케줄링은 "정해진 시간에 정해진 일을 하는 것"이다.** 서버가 아는 건 사용자가 직접 적어준 것이나 허락받고 연결한 것뿐이다.
- **Vercel은 Java 서버를 공식 지원하지 않는다.** 정해진 시간 실행은 Vercel Cron Jobs로 JavaScript 함수를 돌리면 된다.
- 그래서 AI가 대신 초안을 만들려면 **재료를 받는 방법**이 먼저 있어야 한다. 평소에 한 일을 한 줄씩 적어두면, 정해진 때에 그걸 모아 초안을 만드는 방식으로 정리했다.

## 5. 문제 정의와 해결 가설 (초안)

> 회사에서 AI 도구를 따로 지원받지 못하는 직장인은 주간보고처럼 매주 반복되는 정리 업무를 할 때마다, 그동안 한 일을 다시 떠올리고 모아서 처음부터 쓰느라 시간을 쓴다.

> 평소에 한 일을 한 줄씩 적어두기만 하면, 정해진 때에 AI가 그걸 모아 보고서 초안을 만들어둔다. 그러면 보고서 쓰는 시간이 줄어든다.

"한 일을 다시 떠올리고 모으는 게 제일 오래 걸린다"는 부분은 아직 데이터로 확인하지 못한 가설입니다. 어떤 반복 업무로 좁힐지도 인터뷰 결과를 보고 정하겠습니다.

## 6. 오늘 배운 것

1. **비교 기준을 먼저 정해야 결정이 흔들리지 않는다.** 만들기 쉬움, 근거, 시장성 중 무엇을 볼지 정하지 않으면 같은 후보도 평가가 계속 바뀐다.
2. **"이미 있다"는 끝이 아니라 대상과 쓰는 방식을 좁히는 출발점이다.** 해외 서비스는 툴 추천 중심이고 국내는 회사 교육 중심이라, 개인 직장인이 매주 반복하는 업무에는 빈자리가 있을 수 있다.
3. **한 번 쓰고 떠나는 서비스인지, 반복해서 쓰는 서비스인지가 시장성을 가른다.**
