## 문제 정의

반복 업무를 AI에게 맡기는 사람들은 결과를 믿기 어려워 매번 전체를 다시 확인하고 고칩니다. 고쳐야 하면 시간 이득이 사라지고, 다음에 다시 요청해도 같은 설명과 수정을 되풀이합니다. 결국 고치는 일이 줄어드는 경험을 하지 못해서 언제 AI에게 믿고 맡겨도 되는지 판단하지 못하는 상태가 됩니다.


| 구분       | 내용                                                    |
| -------- | ----------------------------------------------------- |
| 대상       | 주간보고, 회의록, 자료 요약, TIL처럼 같은 형식의 글을 AI로 반복해서 쓰는 직장인과 학생 |
| 다루지 않는 것 | AI 결과의 정확도 자체. 정확도는 모델을 만드는 회사의 영역입니다                 |

### 근거의 한계

- 설문 응답자 대부분이 AI에 익숙한 부트캠프 동기라 공개 조사로 보완했습니다. 36명이라 비율보다 분모를 함께 적었습니다.
- 노션, TeamViewer, Connext는 AI·업무 도구를 만드는 회사가 낸 조사이고, Connext와 TeamViewer는 해외 조사입니다.
- 설문 마지막에 아이디어를 보여주고 반응을 물은 문항은 답이 유도됐을 수 있어 근거로 쓰지 않았습니다.
- 자동화를 하지 않는 이유, 고치는 내용이 형식인지 정확성인지는 설문에서 묻지 않았습니다.

## 해결 방안

> 또시켰네는 AI 결과를 고쳤는지 작업마다 기록하고, 고친 내용은 확인을 받아 규칙으로 쌓고, 안 고친 기록이 쌓이면 맡겨볼 만한 때를 알려 줍니다.

### 사용 흐름

사용자는 프롬프트를 쓰지 않습니다. 작업을 설명하고, 결과를 확인하고, 고치기만 합니다.


| 단계      | 사용자                                            | 서비스                                                                      |
| ------- | ---------------------------------------------- | ------------------------------------------------------------------------ |
| 등록      | 질문 4개에 답합니다 (무슨 작업 / 자료 / 결과 모양 / 예전에 잘 나온 결과) | 규칙을 만들어 확인받습니다. 느낀 점처럼 자료에 없는 내용을 써야 하는 규칙은 "자료에 없는 의견도 허용"으로 표시할 수 있습니다 |
| 실행 · 확인 | 자료를 붙여 넣습니다                                    | 결과 줄마다 참고한 곳, 자료에 없음, 근거 확인 필요, 내 생각 줄을 표시합니다. 맞다는 표시는 하지 않습니다           |
| 고치기     | 줄을 고치거나 지웁니다                                   | 고친 줄을 다시 검사하고 규칙 후보를 제안합니다                                               |
| 기록      | 복사될 글을 확인하고 복사합니다                              | 고친 줄이 있었는지로 고침·안 고침을 기록합니다. 띄어쓰기만 고친 건 세지 않습니다                           |
| 맡기기     | 맡길지 직접 정합니다                                    | 3번 연속 안 고침이면 "맡겨볼 만한 때예요"와 함께 정확하다는 뜻은 아니라고 알리고, 지시문을 복사할 수 있게 합니다       |

### 이번 범위와 한계

- 만들지 않은 것: 로그인과 서버 저장, 실제 자동 실행(지시문 복사까지), 확인 생략, 모바일 최적화
- 결과에서 빠진 내용은 표시하지 못하고, 시제 바꿈은 일부만 잡습니다.
- 3번 연속은 검증된 값이 아니라 시연을 위해 정한 임시 기준입니다. 검사 실적에 따라 검사를 줄이거나 늘리는 ISO 2859-1 전환 규칙을 참고했습니다.
- 작업과 기록은 브라우저에만 저장하지만, 입력한 자료는 Gemini 무료 API로 전송되어 Google 서비스 개선에 쓰일 수 있습니다. 첫 화면에서 이를 나눠 알리고 기밀·개인정보를 넣지 말라고 안내합니다.

### Problem (아쉬운 점, 문제)


| 항목               | 내용                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------- |
| 사람 대상 테스트를 못 했다  | 지금까지의 테스트는 모두 제가 정한 시나리오입니다. "이 기록을 보면 맡겨도 되겠다"는 핵심 가설은 아직 검증 전입니다                          |
| 고치는 일이 줄어드는지 모른다 | 같은 자료로 다시 실행하면 지운 줄이 다시 나오는 현상은 6/6에서 0/6으로 줄었지만, 서로 다른 자료로 여러 번 쓰며 고침이 줄어드는지는 사람 데이터가 없습니다 |
| 규칙이 잘 안 쌓인다      | 고쳐도 "이번 자료에만 해당"이면 규칙 후보가 나오지 않습니다. 규칙이 안 쌓이면 "다음엔 덜 고친다"는 약속이 비어 있게 됩니다                    |
| 확인 범위에 빈칸이 있다    | 결과에서 빠진 내용은 표시하지 못하고, 시제 바꿈은 일부만 잡습니다. 긴 자료는 앞쪽 위주로 쓰고, 잘려도 알리지 않습니다                        |
| 모델을 비교하지 못했다     | 모델을 정한 이유가 무료이기 때문인게 아쉽다                                                                    |
| 설문 설계가 아쉬웠다      | 마지막에 아이디어를 보여 주고 반응을 물은 문항은 유도됐을 수 있어 근거로 쓰지 못했습니다. 자동화를 하지 않는 이유는 묻지 않았습니다                 |
| 저장이 브라우저에 묶여 있다  | 가입 없이 바로 쓰게 하려고 브라우저에 저장해서, 다른 기기나 브라우저에서는 기록이 보이지 않습니다                                     |


### Try (다음에 해 볼 것)


| 항목                     | 내용                                                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 박람회에서 사람으로 검증한다        | 박람회에서 사용성 테스트를 하고 "이 기록을 보면 맡겨도 되겠다는 생각이 드나요?"를 물어봐서 데이터 얻어야함                                                                                |
| 규칙이 쌓이게 한다             | 실제로 고친 사례를 모아 규칙 후보 요청을 고치고, 같은 종류를 두 번 고치면 후보를 내는 방식을 검토합니다                                                                                 |
| 빈칸을 알린다                | 자료에는 있는데 결과에 빠진 내용과, 긴 자료가 잘린 것을 화면에 알립니다                                                                                                    |
| AI 모델을 확정한다            | 지금은 무료 한도의 가벼운 모델이고 상위 모델과 비교하지 않았습니다.                                                                                                       |
| 규칙 템플릿에 대한 복제 기능을 추가한다 | 복제기능이 생김으로써 사용자의 경험이 개선될 수 있다.                                                                                                               |
| 사이트 안에서 끝까지 맡기게 한다     | 지금은 완성된 규칙을 지시문으로 복사해 다른 AI에 넘기는 데까지 합니다. 다음 목표는 같은 작업을 사이트 안에서 자동으로 맡기되, 켜진 동안에도 가끔 확인하고 고친 게 나오면 다시 매번 확인하게 하는 것입니다                        |
| 기록이 붙은 규칙을 나눈다         | 그 뒤에는 실제로 몇 번 안 고치고 썼는지 기록이 붙은 규칙을 커뮤니티에서 나눕니다. 규칙 만들기와 직접 실행은 무료로 두고, 자동 실행처럼 AI 호출이 많은 기능은 사용량 제한과 유료 크레딧으로, 규칙 거래가 생기면 수수료로 수익 모델을 검토합니다. |
