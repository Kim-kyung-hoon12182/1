## 6. 최종 결과물 — 테스트 후 남는 것

### 6-1. 사용자가 받는 글 (체험 작업, 확인할 곳 고친 뒤 [복사하고 끝내기])

고친 줄은 ✎ 표시. 직접 복사 칸의 값이 이 7줄과 일치함을 확인했다(S3-41).

```
이번 주 A 프로젝트 마무리 작업을 완료했습니다.
화요일 매출은 9천만 원입니다.
수요일에는 고객 미팅 2건을 완료했습니다.            ✎ (진행했습니다 → 완료했습니다)
목요일에는 QA를 마치고 버그 3건을 수정했습니다.
화요일 매출은 9천만 원이었습니다.                    ✎ ("1억 원으로 목표를 초과" → 자료에 있는 "9천만 원")
전반적으로 팀 분위기가 매우 좋았습니다.              ⚠ 근거 확인 필요 (고치지 않음)
다음 주 일정은 금요일 주간 회의에서 공유했습니다.
```

- "자료에 없음"으로 표시된 줄("1억 원")을 자료에 있는 값으로 고쳤고, **"근거 확인 필요" 줄은 사용자가 그대로 두면 그대로 복사된다.** 앱은 복사를 막지 않고 표시만 한다(정의서 원칙).

### 6-2-1. 남지 않는 것

- **실행 기록(`runs`)은 비어 있다.** 체험 작업의 예시 기록 2건 외에는 쌓이지 않는다(F-06 미구현). 그래서 "맡겨볼 만한 때예요"도 나타날 수 없다.
- **자료·결과·고친 내용은 어디에도 저장되지 않는다.** 화면을 벗어나거나 새로고침하면 사라진다(임시 저장 S3-9 미구현). 복사한 글은 사용자의 클립보드에만 있다.
- 서버로 전송되는 것은 규칙 만들기 때 입력한 답변뿐이다(키가 있을 때). 이번 테스트는 키가 없어 **전송이 한 번도 일어나지 않았다.**

## 7. 테스트하지 못한 것

- **실제 Gemini 호출**: 키가 없어 규칙 생성 성공 경로, 모델명(`gemini-3.8-flash`), 응답 파싱의 실호출, `rate_limit`/`upstream` 분류는 확인하지 못했다(V-03, V-05).
- **Vercel 배포 동작**: 배포 후 확인이 필요하다(V-04, V-08).
- **넓은 화면의 시각적 완성도**: 브라우저 패널이 좁아 수치(넘침, 배치 비율, 위치)로만 점검했다. 실제 모니터에서 눈으로 확인이 필요하다(V-02).
- **클립보드 내용 대조**: 성공 경로는 안내 문구만 확인했고 클립보드 읽기는 권한 제한으로 대조하지 못했다. 실패 경로의 직접 복사 칸은 내용을 대조했다(S3-41).
- **스크린 리더 낭독, 모바일 실기기**: 점검하지 않았다(정의서상 PC 웹이 범위).

사용자 사례: 이미 끝낸 작업을 기록한 글을 요약하면서 "…줄이는 작업을 진행할 예정입니다. [확인 필요]"라고 앞으로 할 일처럼 바꿨다. 값(10분, 10초)은 원문에 다 있어서 일반 검사는 통과하는 줄이고, AI가 스스로 붙인 `[확인 필요]` 덕에만 확인할 곳이 됐다.

**고침**: A) `evidence.ts`에 "예정·계획·할 것입니다·할 것이다·하겠습니다·하겠다"가 줄에만 있고 근거 문장에는 없으면 "근거 확인 필요"로 하는 검사를 더하고 이유 문구를 더했다(사용자 허락을 받아 고침). B) 요청에 "자료의 시제와 사실 상태를 바꾸지 마세요" 한 줄을 더했다.

| 확인한 것 | 결과 |
| --- | --- |
| 단위 테스트(이번 사례와 같은 줄, 근거에도 같은 말이 있는 경우, 약속하는 말, 숫자가 먼저 걸리는 경우) | 10개 통과 |
| 기존 근거 판정 시험(`overlap-test`) | 결과 변화 없음(틀린 줄 중 근거① 12/30, 정상 줄 중 내려감 0/30, 자료에 없는 숫자 탐지 10/10) |
| 예시 작업(체험)의 확인할 곳 수 | 그대로 2개 |
| 실제 AI, 중립 요청 5번 × 글 2개(끝낸 일을 기록한 글, 앞으로 할 일을 제안한 글), 옛 요청과 새 요청 | 앞으로의 말이 든 줄 **0줄**(옛 요청 72줄, 새 요청 85줄 중). 즉 이 사례는 재현되지 않았고, 새 검사가 정상 줄을 잘못 걸러낸 일도 없었다. B 요청 문장의 효과는 오류가 안 나와서 측정하지 못했다 |
| 거짓 경고 위험: 일 설명에 "무엇을 할 계획인지 구분해서"를 넣은 시험 | 계획 서술이 많은 문서에서 "…검증할 계획이다" 같은 줄 26개가 모두 확인할 곳이 됐다. 제안서를 계획으로 풀어 쓴 건 맞는 요약이지만 원문에 "계획"이라는 말이 없어서 걸린다 |

**알아 둘 것**: 이 검사는 원문에 없는 "계획·예정"을 쓴 줄을 모두 확인할 곳으로 올린다. 계획을 다루는 작업이거나 AI가 "계획"으로 풀어 쓰면 맞는 줄도 걸릴 수 있다. 반대 방향("계획"인 것을 "했다"로 바꿔 쓰는 오류)은 잡지 못한다.

## 40. 공통 지시 ㉠㉡과 날짜 비교 (2026-10-12)

조사(`docs/prompt-failure-study.md`) 결과대로 공통 지시에 두 줄을 더하고, 앱의 날짜 비교를 표기에 둔감하게 고쳤다(`evidence.ts`, 사용자 허락).

- ㉠ "자료의 조심스러운 표현(가능성이 있다, ~할 수 있다, 추정, 일부)은 단정으로 바꾸지 말고 그대로 유지하세요."
- ㉡ "날짜와 숫자는 자료에 적힌 표기 그대로 쓰세요(예: 2026. 09. 23.을 2026년 9월 23일로 바꾸지 마세요)."
- 날짜 비교: "2026. 09. 23.", "2026-09-23", "2026년 9월 23일"을 같은 날로 본다. "10월 12일"처럼 연도가 없는 날짜는 자료에 같은 월·일이 있으면 같은 값. 자료에 없는 날짜와 연도가 다른 날짜는 그대로 "자료에 없음".

| 확인한 것 | 결과 |
| --- | --- |
| 날짜 비교 단위 테스트(`date-test`) | 11개 통과(표기 바꿈 3종, 연도 없는 월·일, 없는 날짜, 연도 다른 날짜, 연도를 새로 붙인 날짜, 다른 숫자는 그대로 걸림, 줄 상태) |
| 기존 근거 판정 시험, 시제 시험 | 변화 없음(정상 줄 내려감 0/30, 시제 10개 통과) |
| 새 공통 지시로 5개 자료 × 5번 다시(실제 AI) | 조심스러운 말을 단정으로 **0**(기준 5), 날짜 표기 바꿈 **0**(기준 4), 시제·원인 덧붙임 0. 줄 수는 A=32, B=29, C=100, D=79, E=56으로 기준과 비슷. 근거 문장 어긋남 4(D의 재구매율 줄, 합친 줄 효과), 주체 섞임 1(오탐) |
| ㉡을 일부러 뺀 요청에서 AI가 날짜를 "년 월 일"로 바꿨을 때(실제 AI, 12번) | 바꿔 쓴 줄 **7개 중 "자료에 없음"으로 잘못 표시된 줄 0개** (고치기 전에는 같은 경우가 모두 거짓 경고였다) |

**남은 것**: 날짜만 표기에 둔감하게 했다. "9천만 원"과 "9,000만 원"과 "0.9억 원"처럼 금액·단위를 바꿔 쓴 경우는 아직 다른 값으로 본다(이번 시험에서 AI가 그렇게 바꾼 줄은 0건이었다). ㉢(앞·가운데·뒤에서 고르게)는 결과가 짧아져서 넣지 않았다.

## 41. 고친 내용을 놓치지 않기: 떠나기 전 확인 창과 이번 실행의 정정 (2026-10-12)

사용자 사례: AI가 "12%"라는 값을 지어내서 그 줄을 지우고 다시 실행했는데 같은 값이 계속 나왔다. 원인은 다시 실행이 처음부터 새로 시키는 것이라 지운 내용을 AI가 모르기 때문이다.

**1. 떠나기 전 확인 창**: 고친 곳이 있는 결과에서 [자료 다시 입력]을 누르면 먼저 묻고, 규칙으로 남길 만하면 그 자리에서 규칙 후보를 받아 추가할 수 있다. (수정 직후 바로 제안하는 방식은 고치는 흐름을 끊고 호출이 늘어서 채택하지 않았다.)
**2. 이번 실행의 정정**: 같은 자료로 다시 실행할 때 고치거나 지운 내용을 AI에게 같이 보낸다. 규칙에 저장하지 않는다.

| 확인한 것 | 결과 |
| --- | --- |
| 효과 시험(실제 AI, 숫자 자료 16문장을 한 줄씩 정리, 6번씩): 삭제한 줄 2개와 고친 줄 1개를 정정으로 보냄 | **정정 없이: 삭제한 줄의 내용이 6/6, 6/6번 다시 나옴**(사용자가 겪은 현상과 같음). **정정과 함께: 0/6, 0/6**. 고친 글("72,000원")은 4/6번 그대로 유지, 옛 표현은 0/6 |
| 단위 테스트 | 정정 요청 4개, 정정 병합·변환 3개 포함 규칙 후보 30개, 요청 39개 통과 |
| 화면(AI 응답을 흉내 냄): "12%" 줄 삭제 → [자료 다시 입력] | 통과: "고친 곳 1개가 있어요" 창, "월 매출이 12% 늘었습니다 → 삭제함", [규칙 후보 보기] |
| 규칙 후보 → [규칙 추가] → [이대로 다시 입력] | 통과: 후보 "자료에 없는 퍼센트는 쓰지 않는다", `source: edit`로 저장, 입력 화면에 "이전 결과에서 고친 1곳을 이번 실행에 함께 보내요. 지우기" |
| 같은 자료로 다시 실행하면 AI로 가는 요청 | 통과: "[이번 자료에 대한 사용자의 정정]"과 "1. 삭제함: 월 매출이 12% 늘었습니다."가 들어 있고, 새 규칙도 규칙 목록에 포함. 처음 실행에는 정정 칸이 없었음 |

**한계**
- 정정은 같은 자료로 다시 실행할 때만 간다(자료를 바꾸면 안 간다). 새로고침하면 사라진다.
- AI가 정정을 항상 지킨다는 보장은 없다. 시험한 6번에서는 삭제한 내용이 다시 나오지 않았다.
- 다른 화면으로 나갈 때는 이전처럼 확인 창만 뜬다(고친 내용을 규칙으로 남길 기회는 이 창에서만 준다).
- [한 번 더 실행하기](기록한 뒤)도 고친 내용을 정정으로 가져간다.
