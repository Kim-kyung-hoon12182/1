## 6. 최종 결과물 — 테스트 후 남는 것

### 6-1. 사용자가 받는 글 (체험 작업, 확인할 곳 고친 뒤 [복사하고 끝내기])

고친 줄은 ✎ 표시. 직접 복사 칸의 값이 이 7줄과 일치함을 확인했다(S3-41).

```
이번 주 A 프로젝트 마무리 작업을 완료했습니다.
화요일 매출은 9천만 원입니다.
수요일에는 고객 미팅 2건을 완료했습니다.            ✎ (진행했습니다 → 완료했습니다)
목요일에는 QA를 마치고 버그 3건을 수정했습니다.
화요일 매출은 9천만 원이었습니다.                    ✎ ("1억 원으로 목표를 초과" → 자료에 있는 "9천만 원")
전반적으로 팀 분위기가 매우 좋았습니다.              ⚠ 근거 확인 필요 (고치지 않음)
다음 주 일정은 금요일 주간 회의에서 공유했습니다.
```

- "자료에 없음"으로 표시된 줄("1억 원")을 자료에 있는 값으로 고쳤고, **"근거 확인 필요" 줄은 사용자가 그대로 두면 그대로 복사된다.** 앱은 복사를 막지 않고 표시만 한다(정의서 원칙).

### 6-2-1. 남지 않는 것

- **실행 기록(`runs`)은 비어 있다.** 체험 작업의 예시 기록 2건 외에는 쌓이지 않는다(F-06 미구현). 그래서 "맡겨볼 만한 때예요"도 나타날 수 없다.
- **자료·결과·고친 내용은 어디에도 저장되지 않는다.** 화면을 벗어나거나 새로고침하면 사라진다(임시 저장 S3-9 미구현). 복사한 글은 사용자의 클립보드에만 있다.
- 서버로 전송되는 것은 규칙 만들기 때 입력한 답변뿐이다(키가 있을 때). 이번 테스트는 키가 없어 **전송이 한 번도 일어나지 않았다.**

## 7. 테스트하지 못한 것

- **실제 Gemini 호출**: 키가 없어 규칙 생성 성공 경로, 모델명(`gemini-3.8-flash`), 응답 파싱의 실호출, `rate_limit`/`upstream` 분류는 확인하지 못했다(V-03, V-05).
- **Vercel 배포 동작**: 배포 후 확인이 필요하다(V-04, V-08).
- **넓은 화면의 시각적 완성도**: 브라우저 패널이 좁아 수치(넘침, 배치 비율, 위치)로만 점검했다. 실제 모니터에서 눈으로 확인이 필요하다(V-02).
- **클립보드 내용 대조**: 성공 경로는 안내 문구만 확인했고 클립보드 읽기는 권한 제한으로 대조하지 못했다. 실패 경로의 직접 복사 칸은 내용을 대조했다(S3-41).
- **스크린 리더 낭독, 모바일 실기기**: 점검하지 않았다(정의서상 PC 웹이 범위).

## 18. 사용자 입장 테스트 2차 (2026-10-12, 저장 데이터를 지운 첫 방문 → 안내 → 회의록 작업 만들기 → 실행 4번)

1차와 다른 종류의 작업(회의록)과 지저분한 메모(날짜·이름·금액·"할 수도 있음")로 실제 Gemini에 돌렸다. 키보드(Tab, Ctrl+Enter)와 실제 마우스 클릭을 섞었다.
