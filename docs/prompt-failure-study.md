# AI 결과가 틀리는 방식 조사와 공통 지시 후보 (2026-10-12)

앱이 AI에게 항상 보내는 "공통 지시"(`app/src/lib/runPrompt.ts`)에 무엇을 더할지, 추측이 아니라 실제로 틀리는 방식을 세어서 정했다.

## 방법

- 자료 5개: ① 제안서(표, 가설, 숫자, 앞 8,000자) ② 블로그 글(끝낸 일을 설명) ③ 가능성 표현이 많은 글(새로 만듦) ④ 숫자·단위·날짜가 많은 글(새로 만듦) ⑤ 회의 메모(주체, 결정, 계획이 섞임)(새로 만듦)
- 같은 요청("글을 팀에 공유할 핵심 요약으로 정리한다", 규칙 한 개)을 배포된 AI에 자료당 5번, 총 25번. 앱의 실제 요청 만들기·응답 읽기·근거 바로잡기 코드를 그대로 썼다.
- 틀림을 코드로 센 뒤, 걸린 줄은 눈으로 확인했다. 새 시험 자료 세 개는 짧고 인위적이라 일반화에는 한계가 있다.
- 비교: 같은 자료와 요청에 지시 한 줄 이상을 더해 같은 방식으로 5번씩 다시 돌렸다.

## 1. 기준(추가 지시 없음): 5개 자료 264줄

| 틀림 | 건수 | 눈으로 확인한 결과 |
| --- | --- | --- |
| 날짜 표기를 바꿈 ("2026. 08. 31." → "2026년 8월 31일") | 4 (날짜가 든 자료 133줄 중) | **진짜.** 값은 같은데 표기만 달라서 앱이 "자료에 없음"으로 잘못 표시한다(거짓 경고) |
| 조심스러운 말을 단정으로 ("…나타날 가능성이 있습니다" → "…나타나거나") | 5 (가능성 표현 글 67줄 중) | 일부 진짜(5건 중 약 절반). 나머지는 판정 도구의 오탐 |
| 근거 문장이 어긋남(옮긴 글로 바로잡은 뒤에도) | 6 | 대부분 합친 줄(여러 문장을 합친 요약)이라 대표 근거가 겹치는 경우 |
| 원인·사실을 뒤집음 | 1 | **진짜.** 원문이 "무거웠던 이유는 조건이 아니라 구조였습니다"인데 "무거운 조건으로 인해 비용이 컸다"로 씀 |
| 근거에 없는 사람 이름(주체 섞임) | 1 | 오탐(앞 문장의 맥락상 맞는 서술) |
| **숫자·값이 원문과 다름** | **0** | |
| **끝낸 일을 할 일로(시제)** | **0** | 사용자 사례는 있었지만 이번 시험에서는 재현되지 않음 |
| 범위를 키움(모든·대부분), 일부·약을 뺌, 자료에 없다는 설명 줄 | 0, 1, 0 | |

- **근거 위치(앞/가운데/뒤 1/3)**: 제안서 38/0/0, 블로그 32/12/0으로 앞쪽에 쏠렸다. 짧은 글은 고르게 퍼졌다(③ 32/29/21, ④ 25/23/35, ⑤ 14/19/25).

읽는 법: 중립적인 요약에서는 **숫자를 지어내거나 시제를 바꾸는 일은 거의 없었다.** 많이 나는 것은 표기 바꿈, 조심스러운 말의 단정화, 앞쪽 쏠림이었다.

## 2. 공통 지시 후보를 넣어 비교

| 지시 | 조심스러운 말을 단정으로 | 날짜 표기 바꿈 | 근거 위치(제안서 앞/가운데/뒤) | 줄 수(③④⑤) |
| --- | --- | --- | --- | --- |
| 없음(기준) | 5 | 4 | 38/0/0 | 67, 80, 53 |
| ㉠ 조심스러운 표현은 단정으로 바꾸지 말고 그대로 유지 + ㉡ 날짜·숫자는 자료에 적힌 표기 그대로 | **0** | **0** | 44/0/0(변화 없음) | 100, 79, 48(변화 없음) |
| ㉠ + ㉡ + ㉢ 글의 앞부분만 쓰지 말고 앞·가운데·뒤에서 고르게 핵심을 뽑기 | **0** | **0** | **33/6/4**(완화) | 37, 42, 30(**크게 줄어듦**) |

- ㉠㉡은 목표한 틀림만 없애고 다른 틀림을 늘리지 않았고 줄 수도 그대로였다.
- ㉢은 쏠림을 줄이지만 결과가 짧아졌다(상세 줄이 줄어든다). 짧은 요약이 목적이면 좋고, 줄 단위로 빠짐없이 옮기는 작업에는 맞지 않는다.

## 3. 결론: 무엇을 넣을지

| 후보 | 결정 | 이유 |
| --- | --- | --- |
| ㉠ 조심스러운 표현을 그대로 유지 | **넣는다** | 5→0, 부작용 없음 |
| ㉡ 날짜·숫자 표기를 그대로 | **넣는다** | 4→0, 앱이 거짓 경고를 내는 원인도 줄어듦(앱의 날짜 비교 보완은 별도) |
| ㉢ 앞·가운데·뒤에서 고르게 | **공통으로는 넣지 않는다** | 쏠림은 줄지만 결과가 짧아진다. 대신 "참고 위치 막대"로 쏠림을 사용자에게 보여 주는 쪽을 먼저 한다 |
| 시제 바꾸지 말 것(이미 넣음) | 유지 | 사용자 사례가 있고 정상 줄에 해가 없었다 |
| 숫자를 지어내지 말 것, 범위를 키우지 말 것 | 새로 넣지 않는다 | 이번 시험에서 틀림이 0이라 효과를 재 볼 수 없다. 기존 "자료에 없는 숫자, 이름, 사실은 쓰지 마세요"로 충분 |

## 4. 한계

- 자료당 5번, 새 자료 세 개는 인위적이라 통계로 말할 수 없다. "이 방향이 맞는가"를 보는 수준이다.
- 판정 도구의 정규식은 오탐이 있어서 눈 확인을 같이 했다.
- 사용자가 실제로 고친 내용(수정 기록)에서 나온 규칙 후보를 모으면 더 현실적인 목록이 된다. 그 데이터는 아직 없다(사람 테스트 전).
