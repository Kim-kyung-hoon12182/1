# 지금 상태, 부족한 점, 앞으로의 방향 (2026-10-13)

근거: `docs/test-report.md` 47번(통합 테스트), `docs/open-issues.md`, `docs/prompt-failure-study.md`. 제출 마감은 오늘 21:00이고 제출 뒤에는 URL을 못 바꾼다.

## 1. 지금 되는 것

| 영역 | 상태 |
| --- | --- |
| 핵심 흐름 | 질문에 답해 규칙 만들기 → 자료 넣고 실행 → 줄마다 근거와 확인할 곳 표시 → 고치기·삭제 → 복사하고 기록 → 실행 이력. 실제 AI로 끝까지 통과 |
| 고친 것을 배우기 | 같은 자료로 다시 실행하면 고친 내용을 AI에 같이 보낸다(지운 줄이 다시 나오는 현상이 6/6 → 0/6). 떠날 때 규칙 후보를 받아 규칙으로 남길 수 있다 |
| 정확성을 보장하지 않는 표시 | "참고한 곳 / 근거 확인 필요 / 자료에 없음" 세 가지. 금액·날짜는 표기가 달라도 같은 값이면 통과, 고친 줄은 고친 글로 다시 검사 |
| 맡기는 때 알리기 | 안 고친 기록이 3번 쌓이면 "맡겨볼 만한 때"와 지시문. 안내 모드(13단계)로 처음 사용자가 전 과정을 체험 |
| 품질 | 스크립트 테스트 23묶음 통과, 휴대폰 폭에서 가로 넘침 없음 |

## 2. 부족한 점 (중요한 순서)

| 순위 | 부족한 점 | 왜 문제인가 | 어떻게 |
| --- | --- | --- | --- |
| 1 | **사람 사용자 테스트를 한 번도 안 했다**(V-09) | 이 서비스의 핵심 주장("고친 걸 기록하면 맡겨도 될 때를 안다")이 사람에게 닿는지 모른다. 지금 테스트는 모두 내가 정한 시나리오다 | 제출 뒤에도 3~5명에게 배포 주소로 과제를 시킨다(`docs/user-test-guide.md`). 제출 전에는 팀원 1~2명이라도 처음 보는 눈으로 5분 |
| 2 | **규칙이 잘 안 쌓인다**(N-3) | 고쳐도 "이번 자료에만 해당"이면 후보가 안 나온다. 규칙이 쌓이지 않으면 "다음엔 덜 고친다"는 약속이 비어 있다 | 사용자가 실제로 고친 사례를 모아 후보 프롬프트를 조정. 반복 고침(같은 종류 2번)을 근거로 후보를 내는 방안 검토 |
| 3 | **긴 자료와 앞쪽 쏠림** | 8,000자를 넘으면 조용히 잘리고(알림 없음), 긴 글은 앞쪽 문장 위주로 쓴다 | "앞 8,000자만 썼어요" 알림, 참고 위치 막대(앞/가운데/뒤). 15,000~20,000자 응답 시간 측정 |
| 4 | **확인 검사의 범위** | 빠진 내용, 시제 뒤집힘(계획→했다), 인사말 오탐(N-2), "1억 2천만 원"의 숫자 추출(D-11)은 못 잡거나 어색하다 | 한계로 정직하게 쓰고, 사용자 테스트에서 오탐·누락이 체감되는지부터 본다 |
| 5 | **복사 성공 경로와 다른 브라우저 미확인**(V-01, V-10) | 핵심 버튼인데 일반 Chrome에서 성공을 못 봤고 Safari·Firefox, 오류 화면(429·502·504)도 못 봤다 | 일반 Chrome에서 직접 눌러 복사·붙여넣기, Safari 한 번 |
| 6 | **저장 한계** | 브라우저에만 저장(지우면 사라짐), 임시 저장 없음(I-04), 확인 생략(F-13) 없음, 기기 간 이동 불가 | 제출 범위 밖으로 두되 문서에 명시. 방향 6 참고 |
| 7 | **문구와 용어** | "안 고침 · 복사 안 됨"(N-4), "예시" 세 가지 쓰임(U-09), 첫 화면 선택지 과다(U-07) | 사용자 테스트에서 걸리는 것부터 정리 |
| 8 | **개인정보** | 무료 AI 등급이라 보낸 자료를 Google이 쓸 수 있다고 안내는 하지만 사용자가 고르게 하지는 못한다(V-07) | 제출 전 약관 문구 재확인. 장기적으로 유료 키나 자체 모델 검토 |

## 3. 오늘(제출 전) 할 것

1. 이번 수정(점 날짜 문장 자름)과 문서를 배포하고 배포판에서 같은 자료로 다시 확인
2. 일반 Chrome에서 [복사하고 끝내기] 성공 확인 (V-01)
3. 처음 보는 사람 1~2명에게 "이게 뭘 하는 앱 같아요?"를 물어 첫 화면 문구가 통하는지 확인
4. Gemini 무료 등급 약관 문구 확인 (V-07)
5. 안내 모드를 처음부터 끝까지 한 번 더 눌러 보기

## 4. 제출 뒤 방향

| 시기 | 방향 | 성공을 보는 법 |
| --- | --- | --- |
| 1~2주 | 사용자 테스트 3~5명, 관찰표와 사후 질문으로 "이 기록을 보면 맡겨도 되겠다"가 생기는지 확인(PRD 4-4) | 사용자가 [맡겨볼 만한 때]를 이해하고 지시문을 쓰는 비율 |
| 1~2주 | 후보 프롬프트 개선(N-3), 오탐 문구 조정(N-2, N-4), 8,000자 알림 | 두 번째 실행에서 고친 줄 수가 줄어드는지 |
| 1달 | 임시 저장, 확인 생략(F-13), 규칙 가져오기·내보내기로 기기 이동 | 같은 작업을 3번 이상 다시 실행하는 사용자 수 |
| 이후 | 자료 종류별 규칙 묶음(주간보고·회의록·TIL), 팀 공유는 로그인과 서버 저장이 필요해 별도 결정 | 규칙을 새로 만드는 시간이 줄어드는지 |

## 4-1. 하지 않을 것
- 정확하다고 보장하는 표현, 결과를 "검증했다"는 표현, 자동 승인이나 자동 전송. 이 앱은 "고쳤는지"를 기록해 사람이 맡길 때를 판단하도록 돕는 도구다
- 정의서에 없는 기능 추가(규칙 순서 변경, 규칙 제외 등: D-14). 사용자 테스트에서 필요가 확인될 때만

## 5. 가장 큰 위험
이 서비스의 가치는 "AI가 틀린 곳을 잡아 준다"가 아니라 "내가 고친 것이 쌓여서 다음엔 덜 고친다"는 데 있다. 지금은 그 반 바퀴(고친 것을 같은 자료로 다시 반영, 규칙으로 남기기)까지 되지만, 서로 다른 자료로 여러 번 쓰며 고침이 줄어드는지는 사람 데이터가 없어 확인하지 못했다. 제출 뒤 첫 번째 일은 이 가설을 사람으로 검증하는 것이다.
