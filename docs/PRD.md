## 1. 프로젝트 이름

**또시켰네**

> 또시켰네는 AI 결과를 고쳤는지 작업마다 기록하고, 고친 내용은 확인한 뒤 규칙으로 쌓고, 안 고친 기록이 쌓이면 맡겨볼 만한 때를 알려 줍니다.
>
> 슬로건: 시키는 건 한 번, 반복은 그만. (정확하다는 보장이 아니라, 고치는 일이 줄었는지를 기록으로 보여 준다는 뜻입니다.)

## 2. 문제 정의

> 반복 업무를 AI에 맡기는 사람들은 결과를 믿지 못해 매번 전체를 확인하고 고칩니다. 고쳐야 하면 시간 이득이 사라지고, 다음에도 같은 설명과 수정을 반복합니다. 그래서 AI에게 믿고 맡길 수 있는 상태에 이르지 못합니다.

| 구분 | 내용 |
| --- | --- |
| 대상 | 매번 같은 형식의 글(주간보고, 회의록, 자료 요약, TIL)을 AI로 쓰면서, 대화방에 이어 쓰거나 매번 새로 설명하는 직장인과 학생 |
| 대상 아님 | GPTs·프로젝트에 지시문을 직접 써서 관리하는 사람, 맡길 일을 몰라서 막힌 사람 |
| 다루지 않는 것 | AI 결과의 정확도 자체. 정확도는 모델을 만드는 회사의 영역입니다. |

## 3. 근거

![배경 통계 요약](charts/background-stats.png)

### 3-1. 문제가 있다는 근거

차트의 숫자를 문제 순서대로 읽으면 이렇습니다.

1. **반복 업무에 AI를 쓴다.** 직장인 94.9%가 업무에 AI를 쓰고, 설문 응답자 33/36명이 같은 작업을 여러 번 요청해봤습니다.
2. **결과를 확인하고 고치는 데 시간이 든다.** 97.5%가 AI 결과물을 검증·재편집하고, 56%는 자주·항상 확인하며 주 평균 2시간을 씁니다. 설문에서도 절반이 넘는 19/36명이 확인·수정 시간 때문에 AI를 계속 쓰지 않게 됐다고 답했습니다.
3. **고쳐야 하면 시간 이득이 사라진다.** 수정 없이 맞는 경우는 37%이고, 고쳐야 할 때 직접 하는 것과 시간이 같다는 응답이 46%, 더 걸린다는 응답이 11%였습니다. 설문에서는 16/36명이 매번 수정해야 했다고 답했습니다.
4. **언제 믿어야 할지 모른다.** 결과 신뢰성 부족이 가장 큰 어려움(42.4%)이고, 51%는 언제 믿고 언제 확인할지 항상 알지는 못합니다. 설문에서 AI를 쓸 때 막히는 점으로 가장 많이 고른 것도 결과를 신뢰하기 어렵다는 것(18/36명, 50%)이었습니다.
5. **저장 기능이 있어도 해결되지 않는다.** 같은 작업을 다시 시킬 때 33명 중 22명은 저장 없이 이어 쓰거나 새로 쓰거나 예전 내용을 찾아 복사합니다. OpenAI도 맞춤 지시·프로젝트 같은 기능은 파워 유저 위주로 쓰이고 설정 부담이 장벽이라고 밝혔습니다.
6. **개입할 수 있을 때 맡긴다.** 61%는 AI가 스스로 행동하지 않기를 원하지만, 개입할 수 있다면 70%가 자율 실행을 받아들입니다.

사용자 글에서도 같은 문제가 보입니다. 골라 온 사례라 비율로 해석하지 않습니다.

- "맞춤 지시를 넣어도 무시해서 질문할 때마다 같은 지시를 붙여야 한다." [OpenAI 커뮤니티](https://community.openai.com/t/chatgpt4o-ignoring-prompts-in-instructions-box/1110078)
- "고치면 알겠다고 하고 잠깐 잘하다가 같은 실수가 다시 돌아온다." [OpenAI 커뮤니티](https://community.openai.com/t/goldfish-memory-gpt-5-6-local-intelligence-is-high-but-longitudinal-intelligence-has-become-unreliable/1401345)
- "정말 맞나 싶어 다시 확인하느라, 직접 쓰면 40분이면 끝날 일이 1시간 걸린다." [잡코리아](https://www.jobkorea.co.kr/recruit/careers/articles/ai-burnout-solution)
- "결과를 바로 확인하기 힘든 예약 실행을 시킬 정도로는 AI를 신뢰하지 못한다." (설문 주관식)
- "완전히 똑같은 내용을 복사하는 게 아니라, 복사한 다음 약간 고쳐야 해서 자동화하지 않았다." (설문 주관식)
- "정확할지 의심이 들어서 일단은 아침 식단" (설문 주관식, AI에 맡겨보고 싶은 일을 묻는 문항)

### 3-4. 근거의 한계

- 설문 응답자 대부분이 AI에 익숙한 부트캠프 동기라 공개 조사로 보완했습니다.
- TeamViewer, Delight AI는 자사 서비스와 관련된 조사이고, 해외 조사가 많습니다.
- 블라인드 31.6%는 잡코리아 기사 인용으로만 확인했고 원문은 아직 찾지 못했습니다.
- 설문의 "가장 필요한 기능" 문항에서는 "맡길 반복 업무를 찾아주는 기능"이 17/36명으로 가장 많았습니다. 다만 이 문항의 선택지는 처음 방향(찾기·등록·자동 실행) 기준이라 현재 해결 방안과 직접 비교할 수 없고, 실제로 막히는 점에서 "맡길 일을 모르겠다"를 고른 사람은 5/36명이었습니다.
- 회사 자료나 개인정보를 입력하기 부담스럽다는 응답이 12/36명(33.3%)이었습니다. 그래서 첫 화면에서 저장 위치와 전송 범위를 나눠 알립니다.
- 저장 기능을 안 쓰는 이유와, 고치는 내용이 형식인지 정확성인지는 설문에서 묻지 않았습니다. 사용성 테스트에서 확인합니다.

## 4. 해결 방안

### 4-1. 흐름

사용자는 프롬프트를 쓰지 않습니다. 업무를 설명하고, 결과를 확인하고, 고치기만 합니다.

| 단계 | 사용자가 하는 것 | 서비스가 하는 것 |
| --- | --- | --- |
| 등록 | 질문 4개에 답한다 (무슨 일 / 자료 / 결과 모양 / 예전에 잘 나온 결과) | 기준 5~8개를 만들고 확인받는다 |
| 실행·확인 | 자료를 붙여 넣는다 | 결과 줄마다 "참고한 곳"(AI가 참고한 자료 문장)과 적용 규칙을 보여주고, 자료에 없는 숫자·이름은 "자료에 없음", 근거가 약하거나 AI가 모른다고 쓴 줄은 "근거 확인 필요"로 표시한다. 맞다는 표시는 하지 않는다 |
| 고치기 | 결과를 고치거나 줄을 지운다 | 고친 줄을 다시 검사하고, 규칙 후보를 한 줄로 제안한다. 확인한 것만 저장하고 다음 실행부터 AI에게 보낸다 |
| 기록 | 결과를 복사한다 | 복사할 때 고친 줄이 있었는지로 고침·안 고침을 자동 기록한다. 띄어쓰기만 고친 건 세지 않는다 |
| 기록 보기 | 실행 이력을 본다 | 작업마다 회차별 고친 줄 수를 막대로 보여준다 |
| 맡기기 | 맡길지 직접 정한다 | 3번 연속 안 고치고 쓰면 "맡겨볼 만한 때예요"라고 알린다. 정확하다는 뜻이 아니라는 것도 함께 알린다. "맡겨볼까요?" 창에서 다른 AI 예약 작업에 붙일 지시문을 복사할 수 있다. 지시문은 AI가 아니라 앱이 답변과 규칙으로 만든다 |

**구현 상태 (2026-10-13)**: 위 표의 단계는 모두 배포 주소에서 동작합니다. 첫 방문 안내와 직접 눌러 보며 따라가는 사용 안내(안내 모드)도 있습니다. 처음 계획한 "확인 생략"(확인할 곳이 없으면 결과를 접고 바로 복사)은 만들지 않았습니다(`open-issues.md` I-06).

주간보고로 예를 들면 이렇습니다.

| 회차 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| 결과 | 2곳 고침, 기준 1개 추가 | 1곳 고침 | 안 고침 | 안 고침 |
| 화면 | 확인할 곳 표시로 고칠 곳 확인, 고친 내용으로 규칙 추가 | 추가한 규칙이 요청에 들어감 | | 한 번 더 안 고치면 "맡겨볼 만한 때예요" |

### 4-2. 차별점

개별 기능은 이미 다른 서비스에 있습니다. 또시켰네는 **사용자가 결과를 고쳤는지 작업마다 기록하고, 그 기록으로 맡길지 정합니다.**

| 서비스 | 하는 것 | 없는 것 |
| --- | --- | --- |
| [NotebookLM](https://support.google.com/notebooklm/answer/16179559), [Elicit](https://support.elicit.com/en/articles/14759154-systematic-reviews-in-elicit) | 답변마다 근거 문장 표시, 누르면 원문 강조 | 매번 새 질문이라 같은 일이 나아지는지 기록이 없음 |
| [ChatGPT 메모리](https://help.openai.com/en/articles/8590148-memory-in-chatgpt) | 기준·선호 저장 | 결과를 고쳤는지 모름 |
| [GPTs 빌더](https://help.openai.com/en/articles/8554397-creating-and-editing-gpts) | 대화로 지시문 작성 | 고쳤는지 모름. 개인 계정은 새로 만들 수 없고, 맞춤 GPT는 종료 예정 |
| [Freed](https://help.getfreed.ai/en/articles/11796456-templates-that-learn), [Noumi](https://noumi.ai/features/self-evolving-skills) | 고친 내용을 기준으로 반영 | 그래서 덜 고치게 됐는지 보여주지 않음 |
| [Demi](https://www.demi.ai/how-it-works) | 반복되는 일을 맡기라고 제안 | 반복 횟수만 보고, 고쳤는지는 보지 않음 |
| [ChatGPT 예약 작업](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt) | 정해진 시간에 자동 실행 | 맡겨도 되는지 판단할 근거가 없음. 외부 연동 API 없음 |

참고한 곳 표시(NotebookLM, Elicit), 대화로 기준 만들기(GPTs 빌더), 고친 것을 기준으로 승인(Noumi)은 검증된 방식을 가져옵니다. 새로 만드는 것은 작업마다 쌓이는 수정 기록이고, 맡기기 제안은 Demi의 반복 횟수 대신 이 기록을 기준으로 삼습니다. 조사한 범위 안에서 수정 기록으로 맡기기를 제안하는 서비스는 없었습니다.

### 4-3. 이번 범위

| 이번에 만듦 | 이번에 안 만듦 | 안 만드는 이유 |
| --- | --- | --- |
| 등록, 실행, 참고한 곳·확인할 곳 표시 | 로그인, 서버 저장 | 엑스포에서 가입 없이 바로 쓰게 합니다 |
| 고치기·줄 지우기, 고친 줄 다시 검사, 규칙 후보와 규칙 보기·수정·삭제 | 실제 자동 실행 | 예약 작업에 외부 연동 API가 없습니다. 지시문 복사와 안내까지만 합니다 |
| 수정 기록과 실행 이력, 맡겨볼 만한 때 알림과 지시문 복사 | 확인 생략(F-13) | 마지막 우선순위라 다음 단계로 둡니다 |
| 첫 방문 안내와 사용 안내(안내 모드) | 끝내지 않은 실행 이어서 보기, 다듬기, 익명 사용 기록 | 나갈 때 한 번 묻는 것까지만 만들었습니다 |
| | 모바일 최적화 | PC 웹 기준입니다(좁은 화면에서 깨지지는 않게 했습니다) |

일과 기록은 사용자의 브라우저에만 저장하지만, 결과를 만들 때 입력한 자료는 Gemini API 무료 한도로 전송됩니다. [약관](https://ai.google.dev/gemini-api/terms)상 무료 한도의 입력과 결과는 Google 서비스 개선에 쓰이고 사람이 검토할 수 있어서, 첫 화면에서 저장과 전송을 나눠 알리고 기밀·개인정보를 넣지 말라고 안내합니다.

### 4-4. 만들면서 확인한 것

AI가 낸 결과를 그대로 믿지 않고, 앱이 보여주는 표시가 얼마나 맞는지 직접 재서 설계를 바꿨습니다.

| 확인한 것 | 결과 | 바꾼 것 |
| --- | --- | --- |

3번 연속은 검증된 값이 아니라 엑스포에서 시연할 수 있게 정한 임시 기준입니다. 검사 실적에 따라 검사 강도를 조절하는 방식은 ISO 2859-1 샘플링 검사의 전환 규칙을 참고했습니다. 이 규칙은 연속 10로트 합격 등의 조건을 채우면 수월한 검사로 바꾸고, 불합격이 나오면 보통 검사로 되돌립니다. 확인 생략 중에 고친 실행이 생기면 다시 확인 화면으로 돌아가는 것도 같은 방식입니다. ## 5. 제작 회고

**방향을 바꾼 이유.** 처음에는 AI에 익숙하지 않은 사람에게 맡길 반복 업무를 찾아주고 자동으로 실행하는 서비스를 생각했습니다. 설문을 보니 "맡길 일을 모르겠다"는 5/36명이었고, "결과를 신뢰하기 어렵다"는 18/36명으로 가장 많았습니다. 막히는 곳은 맡길 일을 찾는 단계가 아니라 맡긴 결과를 믿는 단계라고 보고, 믿고 맡길 수 있는 상태를 만드는 쪽으로 바꿨습니다.

**차별점을 다시 세운 과정.** 벤치마킹을 해 보니 근거 표시(NotebookLM, Elicit), 고친 내용을 규칙으로 쌓기(Freed, Noumi), 반복 업무 위임 제안(Demi)이 모두 이미 있었습니다. 기능 하나로는 차별점이 없다는 것을 인정하고, "작업마다 고쳤는지를 기록하고 그 기록으로 맡길 때를 알려 준다"는 연결을 차별점으로 다시 잡았습니다.

**약속을 테스트 결과에 맞춰 줄인 것.** 만들면서 가장 많이 바뀐 것은 기능이 아니라 화면이 하는 말이었습니다. 결과 줄 옆 표시는 "근거 ①"에서 "짚은 곳", "참고한 곳"으로 바뀌었습니다. 낱말 겹침 검사가 틀린 문장 30줄 중 12줄을 통과시킨다는 결과를 보고, 앱이 근거를 확인했다고 말하지 않기로 했습니다. "검토 완료", "정확해요" 같은 말을 쓰지 않고, 안 고친 기록도 "정확하다는 뜻은 아니에요"라고 함께 알립니다.

**AI를 믿지 않고 재 본 것.** AI가 붙인 자료 번호, 겹침 기준값, AI가 틀리는 방식을 모두 실제로 돌려서 셌습니다. 긴 문서에서 번호가 24줄 중 3줄만 맞는다는 것은 직접 재기 전에는 몰랐고, 숫자를 지어내는 일보다 표기를 바꾸거나 말을 단정하는 일이 많다는 것도 세어 보고 알았습니다. 짐작으로 정했다면 틀렸을 결정이 여럿이었습니다.

**제약에서 생긴 선택.** 비용을 쓰지 않으려고 Gemini 무료 한도를 썼고, 무료 한도의 입력이 Google 서비스 개선에 쓰인다는 약관 때문에 저장과 전송을 나눠 알리는 안내를 넣었습니다. 처음 정한 모델은 응답이 불안정해 바꿨습니다. 엑스포에서 가입 없이 바로 쓰게 하려고 로그인 없이 브라우저에 저장했는데, 다른 기기나 다른 브라우저에서는 기록이 보이지 않는 한계가 남았습니다.

**아쉬운 점.**
- 사람 대상 사용성 테스트를 제출 전에 하지 못했습니다. "기록을 보면 맡겨도 되겠다"는 가설은 아직 검증 전입니다.
- 결과에서 빠진 내용을 알려 주지 못합니다. 지금 앱의 가장 큰 빈칸입니다.
- 확인 생략은 만들지 못했고, 맡겨볼 만한 때의 기준 3번은 시연을 위해 정한 임시 값입니다.

**다음 단계.**

- 자료에는 있는데 결과에 빠진 내용을 표시합니다.
- 공부·기록·자료 조사처럼 나누기 쉬운 작업부터, 규칙을 실제로 몇 번 안 고치고 썼는지 기록과 함께 나누는 공간을 검토합니다.
