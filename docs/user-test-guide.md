# 사용성 테스트 가이드 (V-09)

처음 보는 사람 3~5명이 배포 주소(https://ttosikyeotne.vercel.app)로 앱을 쓰는 모습을 보고, PRD 4-4의 세 가설과 이해도를 확인한다. 한 사람당 약 25분.

## 0. 이 테스트로 알고 싶은 것

| # | 확인할 것 | 어떻게 보나 |
| --- | --- | --- |
| H1 | 확인할 곳 표시가 확인하는 방식을 바꾸는가 (PRD 4-4 ①) | 결과에서 어디를 읽는지 관찰. 표시된 곳만 보는지, 전체를 읽는지 |
| H2 | 고친 내용이 규칙이 되는 것을 이해하고 쓸모 있다고 느끼는가 (PRD 4-4 ②) | 규칙 후보 카드 앞에서의 반응과 말 |
| H3 | 기록을 보고 맡겨도 되겠다는 생각이 드는가 (PRD 4-4 ③) | 마지막 질문과 이유 |
| H4 | ChatGPT 같은 걸 직접 쓰는 것과 무엇이 다르다고 느끼는가 | 사후 질문 A |
| H5 | 표시와 용어를 오해하는 곳이 있는가 | 관찰 체크리스트, 사후 질문 B |

이 테스트는 "앱이 좋다"를 확인하려는 게 아니라, **가설이 틀렸는지 알아내려는 것**이다. 불편하거나 모르겠다는 반응이 나오면 그게 결과다.

## 1. 참가자

- 3~5명. **매주 같은 형식의 문서(주간보고, 회의록, 자료 요약 등)를 쓰는 사람**이 대상이다. 그런 업무가 없으면 대상이 아니다(결과를 버리지 않고 "대상 밖"으로 따로 적는다).
- 앱을 만든 사람과 가까운 사람은 가능하면 피한다. 친절하게 봐 주기 때문이다.
- 참가자마다 아래 기본 정보를 적는다: 하는 일, 반복하는 문서와 주기, AI를 얼마나 쓰는지(안 씀/가끔/매주), 자주 쓰는 AI.

## 2. 준비

- 배포 주소를 열 수 있는 PC. 화면 크기 1280px 이상, Chrome.
- **실제 회사 자료를 쓰지 않는다.** 이 앱은 무료 AI 한도를 써서 입력이 Google에 전송되고 사람이 볼 수 있다. 참가자에게 쓸 자료를 미리 준비한 **가짜 메모**로 주거나, 본인이 만든 가짜 자료를 쓰게 한다. 아래 6번 자료 예시를 그대로 써도 된다.
- 참가자 시작 전에 브라우저의 저장 데이터를 지운다(주소창 자물쇠 → 사이트 설정 → 데이터 삭제). 그래야 첫 방문 화면이 나온다.
- 화면과 말을 녹화하거나 메모한다. 녹화는 동의를 받는다.
- 진행자는 **말을 거의 하지 않는다.** 아래 안내 문구 외에는 도와주지 않고, 막히면 "지금 무엇을 하려고 하셨어요?"만 묻는다.

## 3. 진행 순서

### 3-1. 시작 안내 (2분, 그대로 읽는다)

> 오늘은 제가 만든 서비스를 써 보는 자리예요. 서비스를 평가받는 게 아니라, 서비스가 얼마나 이해하기 쉬운지를 보는 거라서 틀리실 일이 없어요. 모르겠거나 이상한 게 있으면 소리 내서 말해 주세요. 제가 도와드리지 못해도 이해해 주세요. 언제든 그만두실 수 있어요. 화면을 녹화해도 될까요? 실제 회사 자료는 넣지 말아 주세요.

### 3-2. 사전 질문 (3분)

1. 지금 반복해서 쓰는 문서가 있다면 무엇이고, 얼마나 자주 쓰세요?
2. 그 문서를 쓸 때 AI를 쓰시나요? 쓴다면 어떻게 쓰세요?
3. AI가 쓴 글을 쓸 때 보통 어떻게 확인하세요?

### 3-3. 과제 (15분)

화면 주소만 알려 주고, 아래 시나리오를 읽어 준다. **사용 안내 버튼이나 기능 이름은 알려 주지 않는다.**

> "당신은 매주 업무 보고서를 쓰는 사람이에요. 오늘은 이 메모(6번 자료)로 보고서를 AI한테 맡겨 보려고 해요. 이 서비스로 보고서 한 편을 만들어서 복사해 보세요. 쓰다가 '이 정도면 됐다' 싶으면 알려 주세요."

- 과제 1: 서비스를 처음 보고 무엇을 하는 서비스인지 말해 보기 (첫 화면에서 30초)
- 과제 2: 보고서 한 편 만들어 복사하기
- 과제 3 (진행자가 자료를 바꿔 한 번 더): 같은 작업으로 **새 메모**를 넣어 한 번 더 실행하기 (7번 자료)
- 과제 4: 실행 이력을 열어 지금까지의 기록을 보고 설명해 보기

### 3-4. 사후 질문 (5분)

질문 순서를 바꾸지 않는다. 대답에 "왜요?"를 한 번 붙인다.

**A. 차별성 (H4)**
1. 이 서비스가 뭐 하는 곳인지 친구에게 설명한다면 어떻게 말하시겠어요?
2. 평소에 ChatGPT 같은 걸 쓰신다면, 거기에 메모를 붙여 넣고 시키는 것과 이 서비스는 뭐가 달랐나요? (다르지 않다고 느꼈다면 그것도 알려 주세요.)
3. 평소 방식이 이 서비스로 바뀔 것 같으세요? 그 이유는요?

**B. 이해와 오해 (H5)**
4. 결과에 나온 "확인할 곳"은 무슨 뜻이라고 생각하셨어요?
5. "확인할 곳"이 하나도 없으면 어떻게 하실 것 같으세요?
6. "참고한 곳", "자료에 없음", "근거 확인 필요"가 각각 무슨 뜻이라고 이해하셨어요?
7. "안 고침"이라는 기록은 무슨 뜻이라고 생각하셨어요?
8. 고친 내용이 "규칙 후보"로 나오는 걸 보고 어떻게 느끼셨어요? 이 규칙이 다음에 어떻게 쓰일 거라고 생각하세요?

**C. 맡길지 판단 (H3)**
9. (기록 화면이나 "맡겨볼 만한 때예요"를 본 경우) 이 기록을 보니 이 일을 AI에게 맡겨도 되겠다는 생각이 드세요? 1(전혀)~5(매우) 중 어디에 가깝고, 이유는요?
10. 맡기려면 어떤 정보가 더 있어야 할 것 같으세요?
11. 이 서비스가 말해 주는 것 중에 믿기 어려웠거나 불안했던 건 없었나요?

**D. 마무리**
12. 가장 좋았던 점 한 가지, 가장 답답했던 점 한 가지.
13. 이 서비스를 다음 주에도 쓸 것 같으세요? 쓴다면 언제, 안 쓴다면 왜요?

## 4. 관찰 체크리스트 (진행 중 진행자가 적는다)

참가자마다 한 장씩 쓴다. 시간은 대략 초 단위, 말은 가능하면 그대로 옮긴다.

| 단계 | 볼 것 | 기록 |
| --- | --- | --- |
| 첫 화면 | 몇 초 만에 무엇을 눌렀나. 사용 안내를 눌렀나, 건너뛰었나 | |
| 첫 화면 | 무엇을 하는 서비스라고 말했나(받아 적기) | |
| 작업 만들기 | 만들었나, 예시로 체험했나, 질문 4개에서 멈칫한 곳 | |
| 자료 넣기 | 어떤 자료를 넣었나, 붙여 넣기에서 막힌 곳 | |
| 결과 읽기 | **어디를 읽었나**: 확인할 곳만 / 전체 / 거의 안 읽음. 읽은 시간 | H1 |
| 확인할 곳 | 표시를 보고 한 행동: 자료에서 보기를 눌렀나, 자료 칸을 봤나 | H1 |
| 고치기 | 고쳤나, 어떻게 고쳤나(숫자·말투·삭제 등), 고치기 버튼을 쉽게 찾았나 | |
| 복사 | 복사하고 끝내기를 눌렀나, "고친 뒤에 눌러야 한다"를 알았나 | |
| 규칙 후보 | 카드를 읽었나, 추가했나, 이번만을 눌렀나, 한 말 | H2 |
| 두 번째 실행 | 첫 번째와 달라진 점을 알아챘나 | H2 |
| 이력·맡겨볼 만한 때 | 기록을 보고 한 말, "안 고침" 해석 | H3, H5 |
| 질문 배너 | "지난번 결과를 복사한 뒤 더 고치셨나요?"에 어떻게 답했나, 무슨 뜻이라고 했나 | H5 |
| 멈칫·오류 | 막힌 곳, 되돌아간 곳, 한숨·"이게 뭐지" 같은 말 | |

**오해 기록**: 참가자가 화면 문구를 앱이 뜻한 것과 다르게 읽은 순간은 바로 별표를 치고, 무엇을 어떻게 읽었는지 그대로 적는다. 특히 아래는 꼭 본다.
- "확인할 곳 0개"를 안전하다는 뜻으로 읽는가
- "참고한 곳"을 맞다는 뜻으로 읽는가
- "안 고침"을 결과가 좋았다는 뜻으로 읽는가
- "맡겨볼 만한 때예요"를 AI가 믿을 만하다는 보증으로 읽는가

## 5. 결과를 읽는 법

사람이 3~5명이라 통계가 아니라 **패턴**을 본다. 한 명의 말보다 둘 이상이 같은 곳에서 막힌 것을 중요하게 본다.

| 가설 | 지지하는 신호 | 지지하지 않는 신호 |
| --- | --- | --- |
| H1 확인 방식 | 결과를 전체가 아니라 표시된 곳 위주로 읽고, 자료에서 보기를 누른다 | 표시를 안 보고 전부 읽거나, 아예 안 읽는다 |
| H2 규칙이 쌓임 | 규칙 후보를 이해하고 추가한다. 두 번째 실행에서 달라진 점을 알아챈다 | 규칙 후보가 뭔지 모르거나, 왜 필요한지 설명 못 한다 |
| H3 기록으로 맡김 | "이 기록이면 맡겨도 되겠다"에 4~5점과 구체적 이유(기록을 근거로 듦) | 3점 이하이거나, 근거를 기록이 아니라 느낌으로 댄다 |
| H4 차별성 | "내가 직접 확인할 곳을 알려 주는 게 다르다", "내가 고친 게 남는다" 같은 설명 | "ChatGPT와 똑같다", "굳이 여기 올 이유가 없다" |
| H5 오해 | 위 오해 항목이 거의 없다 | 두 명 이상이 같은 문구를 오해한다 |

- 가설이 지지되지 않았을 때: **결론을 바꾸는 게 아니라 무엇이 문제인지 적는다.** 예를 들어 "H3 낮음: 기록을 못 이해했다"인지 "기록을 이해했지만 신뢰하지 않았다"인지는 다른 문제다.
- 대상이 아닌 사람(반복 문서가 없는 사람)의 반응은 별도로 적고 통계에서 뺀다.

## 6. 테스트용 자료 (가짜 메모)

**첫 번째 메모**

```
월요일에는 신규 로그인 화면 디자인 시안을 팀에 공유했습니다.
화요일 미팅에서 고객사 요청 3건을 정리했습니다.
수요일에는 결제 오류 2건을 수정하고 배포했습니다.
목요일에는 신규 기능 QA를 마치고 버그 4건을 수정했습니다.
금요일 주간 회의에서 다음 주 일정을 공유했습니다.
이번 주 접속자 수는 지난주보다 늘었으나 정확한 수치는 아직 집계 전입니다.
```

**두 번째 메모** (과제 3, 같은 작업으로 한 번 더)

```
월요일에는 결제 화면 개선안 논의를 진행했습니다.
화요일에 고객 인터뷰 5건을 진행하고 의견을 정리했습니다.
수요일에는 배포 일정을 금요일로 조정했습니다.
목요일에는 신규 알림 기능 개발을 시작했습니다.
금요일 회의에서 이번 주 이슈 2건을 공유했습니다.
```

- 첫 번째 메모의 마지막 줄은 "정확한 수치가 없다"는 점을 일부러 넣어서, AI가 숫자를 지어내는지와 사람이 어떻게 반응하는지를 본다.

## 7. 끝난 뒤 정리

- 같은 날 안에 참가자별 관찰 체크리스트와 사후 질문 답을 정리한다(기억이 흐려진다).
- 발견한 문제는 `docs/open-issues.md`의 V-09 아래에 "참가자 N / 현상 / 심각도"로 옮긴다.
- 숫자로 남길 것: 참가자 수, H3 점수(1~5), 규칙 후보를 추가한 비율, 두 번째 실행에서 달라진 점을 알아챈 비율, 오해가 나온 문구 목록.
- 결과를 PRD 4-4 "2026-10-12 현재" 문단에 사실 그대로 적는다. 가설이 안 지지되었다면 그렇게 적는다.

## 8. 하지 않는 것

- 참가자에게 서비스의 장점을 설명하거나 "이 버튼을 눌러 보세요"라고 알려 주지 않는다.
- 사후 질문에서 "편하셨죠?", "정확하다고 느끼셨죠?"처럼 답을 유도하지 않는다.
- 참가자가 틀렸다고 고쳐 주지 않는다. 틀린 해석이 곧 결과다.
