# 확장 방향 정의서 (초안)

작성일: 2026-10-13 / 수정: 2026-10-15
관계: [요구사항 정의서](PRD.md)는 지금 만든 버전(개인용, 로그인 없음)을 다룹니다. 이 문서는 그 다음에 가고 싶은 방향을 적은 초안이며, 수요를 확인한 결과는 아직 없습니다.

---

## 1. 한 줄 방향

> 지금은 완성된 규칙을 지시문으로 다른 AI에 넘기는 데까지 합니다. 다음 목표는 **같은 작업을 사이트 안에서 끝까지 맡기는 것**이고, 그 뒤에는 **고친 기록이 붙은 규칙**을 커뮤니티에서 나누는 것입니다.

지금 버전이 증명하려는 것은 "내 작업에서 고치는 일이 줄었는지"입니다. 이 기록이 쌓이면 사이트 안에서 바로 맡길 수 있고, 다른 사람에게 보여 주면 규칙을 고를 때의 근거가 됩니다.

---

## 2. 단계

| 단계 | 내용 | 요금 | 필요한 것 |
| --- | --- | --- | --- |
| 1. 지금 | 나만의 규칙 만들기, 고침/안 고침 기록, 맡겨볼 만한 때 알림. 맡길 때는 지시문을 복사해 다른 AI 예약 작업에 붙임 | 무료 | 지금 버전 (브라우저 저장) |
| 2. 사이트 안에서 완성 | 규칙과 업무 양식을 계정에 보관하고, 맡겨볼 만한 작업은 사이트 안에서 정해진 때 자동 실행. 켜진 동안에도 몇 번에 한 번씩 확인하고, 고친 게 나오면 다시 매번 확인 | 기본 무료, 자동 실행부터 유료 검토 | 로그인, 서버 저장, 예약 실행, 자료 가져오기 연동(메일·노션·슬랙 등), 확정한 AI 모델 |
| 3. 공유 | 규칙을 기록과 함께 공개하고, 쓴 사람들이 인사이트를 나누는 커뮤니티 | 무료 | 공개 범위 설정, 민감한 정보 걸러내기 |
| 4. 거래 | 많이 쓰이고 기록이 쌓인 규칙을 사고파는 마켓 | 거래 수수료 | 결제, 판매자 정책, 환불 기준 |

나만의 규칙을 세우고 직접 실행해 기록하는 일은 무료로 둡니다. 기록이 쌓여야 맡기기와 공유의 근거가 생기기 때문입니다.

2단계에서 사이트가 직접 실행해 보내면, 틀린 결과에 대한 부담도 사이트 쪽으로 옵니다. 그래서 켜진 뒤에도 가끔 확인하는 장치는 빼지 않습니다. 검사 실적에 따라 검사를 줄이거나 늘리는 ISO 2859-1 전환 규칙과 같은 방식입니다.

## 3. 수익 모델

| 대상 | 방식 | 이유 |
| --- | --- | --- |
| 규칙 만들기, 직접 실행과 기록 | 무료 (넉넉한 실행 횟수) | 연속 안 고침이 쌓여야 핵심 경험까지 갑니다. 여기를 막으면 기록이 안 쌓입니다 |
| 자동 실행, 긴 자료 처리처럼 AI 호출이 많은 것 | 사용량 제한 + 유료 크레딧 | 비용이 AI 호출에서 나오므로 쓰는 만큼 받습니다 |
| 규칙 거래 | 거래 수수료 | 4단계에서 거래가 실제로 생길 때만 검토합니다 |

- 사용자에게는 "토큰" 대신 "한 달 실행 30번"처럼 실행 횟수나 크레딧으로 보여 줍니다. 토큰은 사용자가 감을 잡기 어려운 단위입니다.
- 크레딧 단가는 모델을 확정하고 1회 실행 비용을 잰 뒤 정합니다(4절).

## 4. AI 모델 확정

지금은 Gemini 무료 한도의 가벼운 모델(`gemini-3.5-flash-lite`)을 씁니다. 처음 정한 `gemini-3.8-flash`는 503 응답이 반복돼 쓰지 못했습니다. 무료 한도와 유료는 같은 모델이라, 무료라서 성능이 낮은 것은 아닙니다. 다만 가벼운 모델이라 판단이 필요한 일에 약할 수 있고, 상위 모델과는 아직 비교하지 않았습니다.

| 확정할 이유 | 내용 |
| --- | --- |
| 품질 | 겹치는 규칙을 못 가리거나 긴 자료 뒷부분을 빠뜨리는 실수가 상위 모델에서 줄어드는지 |
| 안정성 | 자동 실행을 하려면 응답이 안정적으로 와야 합니다 |
| 개인정보 | 무료 한도는 입력이 Google 서비스 개선에 쓰일 수 있습니다. 유료로 가면 달라질 수 있으나 그때 약관을 다시 확인합니다 |
| 비용 | 1회 실행 비용이 크레딧 단가의 기준이 됩니다 |

확정 방법: 프롬프트 연구에 쓴 25회 입력(`docs/prompt-failure-study.md`)을 후보 모델 두세 개에 똑같이 넣어, 얼버무림·날짜 실수·자료에 없음 같은 실수 수와 응답 시간, 1회 비용을 비교합니다. 후보는 공개 순위표(근거 충실도, 지시 따르기, 한국어)로 고릅니다.

## 5. 이미 있는 것과 다른 점

규칙(프롬프트)을 나누거나 파는 기능 자체는 이미 있습니다.

| 서비스 | 하는 일 | 믿게 만드는 방식 |
| --- | --- | --- |
| PromptBase | 프롬프트·스킬 판매 마켓. 약 33만 개 등록, 마켓 판매 시 수수료 20% | 등록 전 심사, 별점, 구매자 후기 |
| GPT 스토어 | 직접 만든 GPT 공개. 수익 배분은 미국 일부 제작자 시범에 그쳤고, 개인 계정의 새 GPT 공개는 막혔으며 GPT 자체를 정리하는 중 | 사용량, 평점 |
| 노션 템플릿 등 | 업무 양식 공유·판매 | 다운로드 수, 후기 |

다른 점은 **믿게 만드는 방식**입니다. 위 서비스들은 별점, 후기, 사용량에 기대고, 실제로 써 봤을 때 고칠 게 줄었는지는 기록하지 않습니다. 또시켰네의 규칙에는 "몇 번 써서 몇 번 연속 안 고쳤는지"가 같이 붙습니다.

이 비교는 2026-10-13에 찾아본 범위입니다. 기록이 붙은 규칙을 거래하는 서비스가 정말 없는지는 더 확인해야 합니다.

## 6. 미리 생각해 둘 위험

1. **사이트가 직접 실행하면 책임이 커집니다.** 지금은 정확도가 모델 회사의 영역이라고 말할 수 있지만, 자동으로 보내는 순간 틀린 결과의 부담이 사이트로 옵니다. 켜진 뒤에도 가끔 확인하는 장치와, 고친 게 나오면 다시 조이는 규칙이 필요합니다.
2. **남의 기록이 내 결과를 보장하지 않습니다.** 그 사람의 자료에서 안 고쳤다는 뜻이지, 내 자료에서도 그렇다는 뜻은 아닙니다. 판매 화면이 "검증된 규칙"처럼 보이면, 지금 버전에서 피해 온 정확도 보장 오해가 돈이 걸린 채로 다시 생깁니다. 기록은 "이 사람이 이렇게 썼다"로만 보여 줘야 합니다.
3. **규칙은 글이라 쉽게 복사됩니다.** 사고팔 가치가 규칙 글 자체보다 기록, 업데이트, 판매자의 관리에서 나와야 합니다.
4. **공유하는 순간 민감한 정보 문제가 커집니다.** 규칙에 사람 이름, 회사 숫자, 고객 정보가 섞일 수 있어 공개 전에 걸러내는 장치가 필요합니다.
5. **기록을 부풀릴 수 있습니다.** 판매자가 쉬운 자료로 안 고침 횟수를 쌓을 수 있습니다. 구매자가 직접 쓴 기록을 따로 보여 주는 방식을 검토해야 합니다.
6. **마켓 수익은 약속대로 안 될 수 있습니다.** GPT 스토어도 수익 배분을 발표했지만 넓게 열지 못했습니다. 거래 단계 전에 공유 단계에서 실제로 규칙을 찾아 쓰는 사람이 있는지 먼저 봐야 합니다.

## 7. 확인할 것

| 질문 | 확인 방법 |
| --- | --- |
| 사이트 안에서 자동으로 맡길 생각이 있는가 | 10/16 박람회에서 "자동화를 안 하는 이유", "여기서 바로 맡길 수 있으면 쓰겠는지" 묻기 |
| 자동 실행에 돈을 낼 생각이 있는가 | 자동 실행 버튼을 두고 누르면 "준비 중"과 관심 등록을 받아 비율 보기 |
| 남이 만든 규칙을 가져다 쓸 생각이 있는가 | 10/16 박람회에서 질문하거나, "다른 사람 규칙 보기" 버튼을 두고 눌러 보는지 확인 |
| 기록이 붙어 있으면 더 믿고 고르는가 | 기록이 있는 규칙과 없는 규칙을 나란히 보여 주고 고르게 하기 |
| 돈을 내고 살 만한 규칙이 있는가 | 공유 단계에서 많이 가져다 쓰인 규칙과 그 이유 보기 |
| 내 규칙을 공개할 생각이 있는가 | 공개 범위를 고르게 했을 때 실제로 공개하는 비율 |

지금은 이 질문들에 대한 데이터가 없습니다. 단계 2 이후는 위 확인 결과를 보고 정합니다.
