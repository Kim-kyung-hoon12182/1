기준 문서: [요구사항 정의서](PRD.md)
앱 위치: `app/` (규칙은 `app/AGENTS.md`)

## 1. 범위

### 1-1. 한 줄 정의

반복하는 문서 작업을 AI에 시키면, 결과에서 확인할 곳을 표시해 주고, 고친 내용을 규칙으로 쌓고, 고쳤는지 기록해서 맡겨볼 만한 때를 알려주는 PC 웹 앱입니다.

### 1-2. 검증할 가설

| 질문 | 확인 방법 |
| --- | --- |
| 검토가 쉬워지는가 | 확인할 곳을 보여줬을 때 오류를 더 빨리, 더 많이 찾는지 |
| 수정이 쌓이는가 | 승인한 규칙이 다음 결과에 반영되어 같은 수정이 줄어드는지 |
| 맡길 의향이 생기는가 | 안 고친 기록을 보고 검토 수준을 낮춰보려 하는지 |

성공은 맡기기 버튼을 누른 횟수가 아니라, 같은 일을 반복할수록 검토 부담과 같은 수정이 줄어드는지로 봅니다.

### 1-3. 다루는 일

자료를 넣으면 글이 나오는 반복 업무를 다룹니다. 설문(2026.10.07~09, 전체 32명)에서 가장 번거로운 반복 업무 문항에 답한 27명 중 21명(77.8%)이 여기에 해당했습니다. 이 문항은 앞 문항에서 반복 업무를 고른 사람만 답해서 분모가 27명입니다. PRD와 소개 자료도 같은 원본(32명)의 숫자를 씁니다.

| 다룸 | 다루지 않음 |
| --- | --- |
| 업무보고·보고서, TIL·블로그·개인 기록, 자료 조사·요약, 회의록, 공지, 이메일 | 일정 관리, 엑셀 데이터 정리, 파일 백업처럼 다른 도구에서 해야 하는 일 |

### 1-4. 원칙

- 확인할 곳 표시는 정확성을 보증하지 않습니다. 앱이 검사한 범위만 말하고, 신뢰 신호(초록 "맞음")는 주지 않습니다.
- 안 고친 기록은 맡겨볼 만하다는 신호일 뿐, 안전하다는 증거가 아닙니다. 맡길지는 사용자가 정합니다.
- "안 고침"은 결과를 바꾸지 않았다는 뜻이지 검토를 마쳤다는 뜻이 아닙니다. 고침 여부와 넘긴 방식을 따로 기록합니다. 화면을 일정 시간 봤다는 것도 검토를 마쳤다는 뜻으로 쓰지 않습니다.
- 규칙은 사용자가 확인한 것만 저장합니다. AI가 규칙을 마음대로 바꾸지 않습니다.
- AI가 하는 작업마다 AI 없이 대신할 방법을 둡니다. 하나가 막혀도 앱이 멈추지 않게 합니다.
- 기록은 사용자가 원래 하던 행동(복사)에 붙입니다. 기록만을 위한 버튼을 따로 누르게 하지 않습니다.
- 처음 온 사람이 30초 안에 확인할 곳 표시를 보게 합니다.
- 상태는 색과 글자 라벨을 함께 씁니다.
- 어디에 저장되고 어디로 전송되는지 구분해서 알립니다.

### 1-5. 우선순위

| 구분 | 목표 | 기능 |
| --- | --- | --- |
| P0 반드시 | 핵심 가치를 직접 경험하게 한다 | 작업 등록과 규칙 만들기, 실행, 확인할 곳 표시와 근거 이동, 고치고 복사, 수정 기록 유지, 실패 안내와 예시 체험 |
| P1 차별점 | 반복할수록 나아지는 걸 보여준다 | 고친 내용에서 규칙 후보, 승인한 규칙 반영, 최근 기록 표시, 맡겨볼 만한 때 제안, 지시문 복사, 확인 생략(P1 마지막) |
| P2 제출 전 생략 | 시간이 남으면 | 익명 사용 기록, 가짜 버튼, 다듬기, 빠진 자료 표시, 실행 기록 상세, 일 정보 수정 |

P1이 밀리면 규칙 후보 승인 흐름을 먼저 완성하고, 맡기기 제안은 체험용 작업(예시 표시)로 시연합니다.

## 2. 데이터 저장과 전송

| 데이터 | 저장 위치 | 외부 전송 |
| --- | --- | --- |
| 일, 질문 답변, 규칙 | 이 브라우저 (localStorage) | 실행·규칙 만들기 때 Gemini로 전송 |
| 자료, AI 결과, 고친 결과 | 이 브라우저 | 실행·규칙 후보 만들 때 Gemini로 전송 |
| 실행 기록 (고침 여부, 넘긴 방식, 확인할 곳 개수, 경과 시간, 복사 성공) | 이 브라우저 | 전송 안 함. 이번 제출 버전은 익명 사용 기록을 수집하지 않음 (F-11은 P2) |
| API 키 | 서버 환경 변수 | 브라우저에 노출하지 않음 |

이 앱은 결제 정보를 연결하지 않은 Gemini API 무료 한도(약관상 Unpaid Services)를 씁니다. [Gemini API 추가 약관](https://ai.google.dev/gemini-api/terms)에 따르면 무료 한도에서는 Google이 입력한 내용과 생성된 결과를 제품·서비스와 머신러닝 기술을 개선하는 데 쓰고, 사람 검토자가 입력과 결과를 읽을 수 있습니다(검토 전에 계정·API 키와의 연결은 끊습니다). 약관도 민감한 정보, 기밀, 개인정보를 넣지 말라고 안내합니다. 그래서 첫 방문 안내에서 저장과 전송을 나눠 알립니다. 2026-10-09에 약관 원문을 확인했고, 제출 전에 한 번 더 확인합니다.

## 3. 화면 목록과 흐름

| ID | 화면 | 목적 | 우선순위 |
| --- | --- | --- | --- |
| S0 | 첫 방문 안내 | 저장·전송 범위와 기밀 입력 주의 | P0 |
| S1 | 내 작업 목록 | 작업과 최근 기록 보기, 체험 시작 | P0 |
| S2 | 작업 등록 | 질문에 답해 규칙 만들기 | P0 |
| S3 | 실행·결과 | 자료 넣고 결과 확인, 고치고 복사 | P0 |
| S4 | 규칙 추가 확인 | 고친 내용을 다음에도 적용할지 묻기 (S3 위 카드) | P1 |
| S5 | 맡겨볼 만한 때 | 안 고친 기록을 보여주고 다른 곳에 맡기는 지시문을 줌. 검토 수준(확인 생략)을 고르는 부분은 F-13이라 아직 없음 (S3 위 카드, S1 태그에서도 창으로 열림) | P1 |
| S6 | 규칙 목록 | 규칙 보기·수정·삭제 (S1 위 패널) | P1 |

```
첫 방문 → S0 → S1
S1 ─[체험해보기]→ S3 (체험용 작업, 3회차 자료가 채워진 상태)
S1 ─[새 작업 등록 / 예시 작업]→ S2 → S3
S1 ─[작업 카드]→ S3
S3 ─[복사하고 끝내기]→ ① 복사 ② 실행 기록 확정
                     ├ 고친 줄 있음 → S4 (건너뛰어도 기록은 이미 남음)
                     └ 고친 줄 없음 → 조건 충족 시 S5
S5 ─[확인 생략 켜기]→ 다음 실행부터 확인 생략 화면 (F-13, 아직 만들지 않음)
S1 ─[규칙 보기]→ S6
```

화면 전환은 라우터 라이브러리 없이 주소의 `#` 뒤(`#/`, `#/create`, `#/run/<작업 id>`, `#/history`)와 `App.tsx`의 상태로 합니다. 뒤로가기·새로고침·링크가 되고, 복사하지 않은 결과가 있으면 나갈 때 한 번 묻습니다.

#### 안내 모드 (S0에서 시작, 상단 [사용 안내]로 다시 시작)

화면 전체를 회색 블러로 덮고 지금 누를 곳만 밝게 보여 준다. 사용자가 그 버튼을 실제로 누르면 다음 단계로 넘어간다(누를 결과를 보여 주기만 하는 9·11·15단계는 말풍선의 [다음] 버튼으로 넘어간다). 체험용 작업(F-09)로만 돌려서 AI 키가 없어도 되고 실제 작업과 섞이지 않는다.

| 1 | S1 | [예시로 체험해 보기] | 예시로 먼저 해 볼게요. 눌러 보세요. | 그 버튼 누름 |

| 막는 범위 | 밝게 보이는 곳 밖은 눌리지 않는다. 스크롤은 된다. 막힌 곳을 누르면 강조 테두리가 한 번 흔들리고 말풍선에 "지금은 표시된 곳을 눌러야 다음으로 넘어가요. 그만하려면 [건너뛰기]를 누르세요."가 2.6초 나온다(단계가 바뀌면 사라짐). 같은 이름의 다른 버튼을 눌러도 반응이 없는 문제를 막으려는 것 |
| 입력칸 단계 | 7단계는 입력칸에 바로 커서가 가고, 막힌 곳을 눌러도 입력칸의 포커스가 풀리지 않는다. 규칙 후보는 AI가 만들어서 안 나오거나 비어 있을 수 있으며(오프라인·키 없음 포함), 그러면 10·11단계는 건너뛴다 |
| 기다리는 중 표시 | 눌러야 할 버튼이 아직 안 나왔을 때(10단계에서 AI가 규칙 후보를 만드는 중) 말풍선에 돌아가는 표시와 "만들고 있어요. 잠시만 기다려 주세요."를 보여 주고, 후보 카드에도 같은 표시가 돈다. 버튼이 나오면 사라진다 |
| 키보드 | 시작하거나 단계가 바뀌면 포커스가 말풍선으로 간다. Tab은 눌러야 할 곳과 말풍선 안에서만 돌고 흐려진 곳으로 나가지 않는다. 눌러야 할 곳에서 Enter로도 다음 단계로 간다 |
| 끝 카드의 단계 표시 | 조건부 단계(10·11·12단계)를 건너뛰었으면 "15 / 15"를 띄우지 않는다 |
| 같이 밝게 보이는 곳 | 바로 앞 동작의 결과를 함께 밝게 보여 준다. 3단계는 넣은 자료 칸, 4단계는 나온 결과 줄, 5·6단계는 옮겨 간 자료 칸과 오른쪽에서 고른 줄 카드, 7단계는 기록한 카드다. 눌러도 반응하지 않고 안내만 흔들린다. 말풍선은 이 곳을 피해 놓는다 |
| 스크롤 | 사용자가 스크롤해서 눌러야 할 곳이 위에 고정된 영역(결과 요약 등) 밑에 가려지면, 스크롤이 멈춘 뒤 0.5초 지나 화면 가운데로 다시 가져온다. 고른 줄 카드처럼 눌러야 할 곳을 품은 곳은 전체를 밝게 하되 눌러야 할 곳 둘레만 막는다 |
| 길을 잃었을 때 | 다음 단계의 요소가 3초 넘게 안 보이거나 다른 화면으로 가면 안내를 끝낸다 |
| 기록 | 8단계의 기록은 체험용 작업(`mitgo:demo`)에만 남고 [체험 초기화]로 지운다. 안내를 시작할 때 체험용 작업을 처음 모양(1·2회차 안 고침)으로 되돌려, 3회차를 안 고치고 복사하면 7단계가 나오게 한다 |
| 12단계(맡겨볼 만한 때)가 안 나오는 경우 | 확인할 곳을 5초 안에 넘겼거나 복사가 안 되거나 7단계에서 글을 고쳐서 3번째 기록이 연속에 안 들어가면 12단계는 알리지 않고 건너뛰고 마무리 카드로 간다. 이유는 완료 카드가 "빠르게 넘겨서 연속 안 고침에 넣지 않아요"로 알려 준다 |
| 이미 쓰던 사람 | 저장된 작업이 있으면 S0을 자동으로 띄우지 않는다. [사용 안내]로 직접 시작할 수 있다 |

### S3. 실행·결과

```
┌ 주간보고 · 3회차 ─────────────── 최근 [고침][고침] ─┐
│ ┌ 자료 ──────────────────┐ ┌ 결과 ─────────────────────┐ │
│ │ ① 월: A 프로젝트 마무리 │ │ · 팀장님께 이번 주 업무를…  │ │
│ │ ② 화: 매출 9천만 원     │ │   참고한 곳 ①                │ │
│ │ ③ 수: 고객 미팅 2건     │ │ ▌매출 1억 2천 달성          │ │
│ │                          │ │ ▌자료에 없음: "1억 2천"     │ │
│ │                          │ │ ▌회의가 많았습니다          │ │
│ │                          │ │ ▌근거 확인 필요             │ │

│                                        [복사하고 끝내기]   │
└────────────────────────────────────────────────────────────┘
```

| ID | 요소 | 내용 | 동작 |
| --- | --- | --- | --- |
| S3-1 | 머리말 | 작업 이름, 회차, 최근 기록 칩. 예시 결과면 "예시 결과예요" | 없음 |
| S3-2 | 자료 칸 (왼쪽) | 실행 전 붙여넣기 칸(8,000자, 글자 수 표시). 실행 후 문장마다 번호가 붙은 읽기 화면 | [다시 입력] |
| S3-3 | 실행 | 자료가 비면 비활성 | F-03, 로딩 중 "결과를 쓰고 있어요" |
| S3-4 | 결과 줄 (오른쪽) | 줄마다 글과 상태 표시 | 클릭하면 선택되어 S3-5. 선택된 줄 오른쪽에 [고치기]. 누르면 그 줄만 입력칸이 되고 Enter 또는 바깥 클릭으로 끝냄. 고친 줄은 "고침" 표시, [되돌리기] 가능. **줄 삭제**: 선택된 줄과 한 줄 모양의 줄에 [삭제]. 누르면 그 줄이 취소선과 "삭제함"으로 바뀌고 한 줄 모양으로 접히며, [되돌리기]로 복구한다. 삭제한 줄은 복사에서 빠지고, 확인할 곳·상태별 줄 수 계산에서 빠지며, 위쪽 집계에 "삭제 N줄"로 따로 나온다. 기록한 뒤에는 삭제·되돌리기 모두 할 수 없다 |
| S3-5 | 강조 | 선택한 줄이 가리키는 자료 번호를 왼쪽에서 노란색으로 강조하고 스크롤. "AI가 지켰다고 한 규칙"을 줄 아래에 작게 표시(앱이 확인한 것이 아니라 AI가 말한 것이다) | 다른 줄 클릭 시 바뀜 |
| S3-6 | 상태 표시 | F-04의 세 상태. "참고한 곳 ①"은 회색 작은 글씨로 AI가 참고한 자료 위치만 알림. 마우스를 올리면 "AI가 이 줄의 근거라고 참고한 자료예요. 뜻이 맞는지는 확인하지 않았어요". "자료에 없음"과 "근거 확인 필요"는 주황 배경과 글자 라벨로 크게 | 없음 |
| S3-7 | 확인할 곳 | "확인할 곳 N개" + 검사 범위 안내 한 줄. 0개면 "자동 검사에서 따로 확인할 곳을 찾지 못했어요. 그렇다고 안전하다는 뜻은 아니에요." | [첫 번째로 이동], [다음] |
| S3-7a | 참고 범위 | 결과 아래에 "자료 N문장 중 M문장을 참고했어요"(N은 표 구분선·마크다운 제목·4글자 미만 줄을 뺀 내용 있는 문장 수). 어느 결과 줄도 참고하지 않은 자료 문장이 있으면 번호와 함께 접어서 보여 주고, 누르면 자료 칸이 그 문장으로 이동한다. 빠뜨렸다는 판정이 아니라 확인해 보라는 목록이다. 모두 참고됐어도 "내용을 빠짐없이 옮겼다는 뜻은 아니에요"를 붙인다. 삭제한 줄이 참고한 문장은 참고된 것으로 세지 않는다 | 자료 문장 클릭. **요약 모드**: 내용 있는 문장이 10개 이상이고 결과 내용 줄이 그 절반에 못 미치면 목록 없이 "자료 N문장을 M줄로 줄여 쓴 요약이에요. 줄마다 대표 근거만 표시해서 참고 표시가 있는 문장은 K개예요. 줄인 만큼 빠진 내용이 있는 게 당연하니, 꼭 필요한 내용이 들어갔는지는 직접 확인해 주세요."만 보인다(AI는 줄마다 대표 근거 하나만 달아서, 합친 문장이 많은 요약에서는 이 숫자가 실제 반영보다 작다) | 자료 문장 클릭 |

- 이번 자료에만 해당하는 사실 정정이면 AI가 빈 문자열을 주고, 카드를 띄우지 않습니다.

- 카드를 건너뛰거나 닫아도 실행 기록은 이미 남아 있습니다.
- 나가기 확인(2026-10-12): 복사하지 않은 결과가 화면에 있을 때 다른 메뉴·뒤로가기·[자료 다시 입력]을 누르면 "아직 복사하지 않은 결과가 있어요. 지금 나가면 이 결과와 고친 내용이 사라져요. 나갈까요?"를 한 번 묻고, 탭을 닫거나 새로고침할 때는 브라우저 경고를 건다. [복사하고 끝내기]로 기록을 남기면 묻지 않는다. 결과를 아직 안 만들었을 때도 묻지 않는다.

| 완료 기준 | 질문에 답하고 [규칙 만들기]를 누르면 규칙이 뜨고, 고친 뒤 저장할 수 있다 |

### F-03. 실행

| 항목 | 내용 |
| --- | --- |
| 입력 | 자료(8,000자), 규칙 목록, 질문 3(결과 모양) |
| 전처리 | 자료를 줄바꿈과 문장 끝 기준으로 나눠 1번부터 번호를 붙인다 |
| 요청 | 번호 붙은 자료 + 번호 붙은 규칙 + "자료의 조심스러운 표현(가능성이 있다, 추정, 일부)을 단정으로 바꾸지 말 것", "날짜와 숫자는 자료의 표기 그대로 쓸 것", "자료의 시제와 사실 상태를 바꾸지 말 것(끝난 일은 끝난 일로, 계획은 계획으로)" + "결과를 줄 단위로 쓰고, 줄마다 근거 자료 번호, **그 자료 문장에서 그대로 옮긴 짧은 글**, 적용한 규칙 번호를 JSON으로. 자료에 없는 내용은 쓰지 말 것" |
| 응답 형식 | `{ "lines": [{ "text": "", "sourceIds": [1], "sourceQuotes": ["옮긴 글"], "ruleIds": ["r1"] }] }` |
| 후처리 | 존재하지 않는 자료·규칙 번호는 버린다. **근거 번호 바로잡기**: AI는 긴 자료에서 번호를 자주 틀리지만 글을 옮기는 건 잘해서, 옮긴 글(`sourceQuotes`)이 자료의 어느 문장에 들어 있는지 앱이 찾아 그 문장 번호를 근거로 쓴다. 글이 한 문장에 통째로 없으면 표의 칸(`\|`) 단위(8글자 이상)로 나눠 찾고, 같은 글이 여러 문장에 있으면 AI가 준 번호와 겹치거나 가까운 문장을 쓴다. 글을 못 찾거나 4글자보다 짧으면 AI가 준 번호를 그대로 쓴다. 옮긴 글은 저장하지 않는다. 그다음 F-04 (`lib/citation.ts`) |
| 대안 | JSON이 깨지면 글로 받아 줄 단위로 자르고 `sourceIds`는 비운다 |
| 완료 기준 | 결과가 줄 단위로 나오고, 실패해도 자료가 지워지지 않는다 |

### F-04. 확인할 곳 표시

AI가 붙인 자료 번호는 "AI가 참고했다고 한 곳"일 뿐 검증이 아닙니다. 앱이 직접 비교한 결과로 상태를 정하고, 위에서부터 먼저 걸리는 것으로 정합니다.

| 순서 | 조건 | 상태 | 표시 |
| --- | --- | --- | --- |
| 0 | 소제목 줄: `[완료한 일]`, `1. 완료한 일`, `## 제목`, `■ 제목`, `제목:` 중 하나의 표시가 있고 20자 이하, 숫자 없음, 문장으로 끝나지 않음 (`lib/heading.ts`) | `heading` | 회색 "제목". 확인할 곳 수와 연속 계산에 넣지 않는다. 자료와 맞춰 보지 않는다 |
| 0 | AI가 줄에 `[확인 필요]`라고 적음(프롬프트가 "모르는 부분은 [확인 필요]라고 쓰세요"라고 시킴). 소제목 다음, 자료 비교 전에 본다 | `needs_check` | 주황 "근거 확인 필요". 이유: "AI가 자료에서 알 수 없다고 [확인 필요]로 적은 곳이에요. 자료를 보고 직접 채워 주세요." 근거 번호가 있어도 확인할 곳으로 올린다 |
| 1 | 줄의 숫자·날짜·이름 후보 중 자료 전체에 없는 것이 있음. **고친 줄은 고친 글로 다시 검사한다(자료에 없는 숫자·이름과 [확인 필요]만 다시 걸고, 되돌리면 AI 글의 판정으로 복귀).** **금액은 표기가 달라도 같은 값이면 같은 값으로 본다**("9천만 원" = "9000만 원" = "9,000만원" = "0.9억 원" = "90,000,000원", 값이 다르면 그대로 걸린다). **날짜는 표기가 달라도 같은 날이면 같은 값으로 본다**("2026. 09. 23." = "2026-09-23" = "2026년 9월 23일", 자료에 "10월 12일"만 있으면 연도 없는 "10월 12일"도 같은 값). 자료에 없는 날짜, 연도가 다른 날짜, 자료에 없는 연도를 새로 붙인 날짜는 그대로 걸린다 | `not_in_input` | 주황 "자료에 없음: {값}" |
| 2 | 자료 번호가 없거나, 참고한 자료 문장과 거의 관계없거나(겹침 0.3 미만), 결과를 뒤집는 말이 자료 문장에 없음, 또는 **"예정·계획·하겠습니다·할 것이다" 같은 앞으로의 일을 뜻하는 말이 줄에만 있음**(끝낸 일을 할 일로 바꿔 쓴 시제 오류를 잡으려는 것, `FUTURE_WORDS`) | `needs_check` | 주황 "근거 확인 필요" |
| 3 | 1·2번에 걸리지 않음 | `has_source` | 회색 "참고한 곳 ①". AI가 참고한 위치를 보여줄 뿐, 앱이 근거를 확인했다는 뜻이 아니다 |
| 2-1 | **자료 밖 허용 규칙**(규칙의 "자료에 없는 의견도 허용" 체크)을 AI가 지켰다고 적은 줄이 2번(근거 확인 필요)에 걸렸을 때. 1번(자료에 없는 숫자·이름)과 AI가 적은 `[확인 필요]`는 그대로 남는다. TIL의 느낀 점·다짐 같은 줄이 경고로 보이지 않게 하려는 것이다 | `opinion` | 회색 "내 생각 줄". 확인할 곳에 세지 않고, "맡겨볼 만한 때"의 연속 판단에서도 확인할 곳으로 세지 않는다. 자료와 맞춰 보지 않았다는 뜻이고 내용이 맞다는 뜻은 아니다 |

| 항목 | 내용 |
| --- | --- |
| 숫자 검사 | 숫자가 들어간 덩어리(1억 2천, 30%, 10/9, 3건)를 뽑아 쉼표·공백을 지우고 자료에 같은 글자가 있는지 본다. AI를 쓰지 않는다 |
| 이름 검사 | 따옴표 안 글자, 영문 대문자로 시작하는 단어만 이름 후보로 보고 같은 방식으로 확인한다. 따옴표 없는 한국어 인명·회사명은 잡지 못하고, 대문자 단어 중 고유명사가 아닌 것도 섞인다. 그래서 화면 안내는 "숫자·날짜·이름"이 아니라 "자동 검사는 숫자·날짜와 일부 이름(따옴표 안 글자, 영문 대문자 단어), 근거 위치만 봐요."로 범위를 좁혀 쓴다 |
| 겹침 검사 | 줄과 참고한 자료 문장을 낱말(2글자 이상, 조사 제거)로 나눠, 줄 낱말 중 자료 문장에 있는 비율을 본다. 기준값은 상수 `SOURCE_OVERLAP_MIN = 0.3`으로 두고 예시 자료로 조정한다 |
| 뒤집는 말 검사 | 줄에 실패·취소·지연·연기·중단·보류·미완료·못·않·없 같은 말이 있는데 참고한 자료 문장에는 없으면 2번으로 내린다. 목록은 상수 `FLIP_WORDS`로 두고 예시 자료로 늘린다 |
| 자료 밖 허용 | 규칙에 체크하면 요청에 그 규칙 뒤에 "[자료 밖 허용]"이 붙고, 공통 지시에 "이 표시가 붙은 규칙을 지키는 줄만 자료에 없는 의견·느낀 점·다짐을 써도 된다. 그 줄의 ruleIds에 규칙 번호를 넣고, 숫자와 이름은 그 줄에서도 자료에 없는 것을 쓰지 말라"는 예외가 더해진다(허용 규칙이 있을 때만). AI가 규칙을 지켰다고 적기만 하면 검사를 피하므로 숫자·이름 검사와 `[확인 필요]`는 그대로 둔다 |
| 한계 | 겹침이 충분해도 의미가 맞다는 뜻은 아니다. 뒤집는 말 검사로 "고객 미팅 2건 진행"을 "고객 미팅 2건 모두 실패"로 바꾼 경우는 잡지만, 주어를 바꾸거나("A팀"→"B팀", 둘 다 자료에 있을 때) 평가를 덧붙인 경우("성공적으로")는 못 잡는다. 그래서 3번도 신뢰 표시를 하지 않는다. "1억 2천"과 "120,000,000"처럼 표기가 다르면 1번에 걸린다 |
| 기준값 성격 | `SOURCE_OVERLAP_MIN = 0.3`은 정확도 기준이 아니라 근거 위치를 안내하기 위한 임시 값이다 |
| 조정 방법 | 아래 "겹침 기준 테스트" 표대로 한다 |
| 대안 | 겹침 기준 테스트 결과로 적용했다(아래). 겹침 검사는 "근거가 있다"를 판단하지 않고, 거의 관계없는 문장을 참고한 경우만 "근거 확인 필요"로 내리는 데 쓴다. 3번 표시는 "근거 ①"에서 "참고한 곳 ①"으로 바꿨다 |
| AI 번호 정확도 | 측정함(2026-10-11, `gemini-3.5-flash-lite`, 자료 10개). 번호가 모두 맞은 자료 7/10(기준 7개 이상 충족), 내용 줄 단위로는 43/49(88%). 틀린 6줄은 ①AI가 자료에 없는 평가·전망을 덧붙인 줄 2개(요약 2건), ②번호를 아예 안 붙인 줄 4개(회의록 1건)였고, 앱 검사가 6줄 모두 "근거 확인 필요"로 내려서 틀린 줄이 "참고한 곳"을 받은 경우는 0이다. 기준을 넘었으므로 3번 표시("참고한 곳 ①")는 유지한다. 표본이 작고 줄 판정은 사람이 읽고 했다 |
| 완료 기준 | 자료에 없는 숫자가 든 줄은 항상 "자료에 없음"이다. 번호가 없거나 관계없는 문장을 참고했거나 뒤집는 말이 든 줄은 "근거 확인 필요"다. 어떤 줄도 "맞음"류나 "근거 있음"류 표시를 받지 않는다 |

| 기준값 | 틀린 줄 중 "근거 ①" | 정상 줄 중 "근거 확인 필요" | 자료에 없는 숫자 중 "자료에 없음" | 판단 |

판단

- 대안을 적용한다. 0.2~0.4 사이에서는 결과가 같았고, 틀린 줄의 40%(12/30)가 3번 상태를 받았다. 자료 문장에 사실을 덧붙인 줄은 겹침이 0.44 이상이라 낱말 겹침으로는 걸러지지 않는다.

### F-06. 수정 기록

[복사하고 끝내기]를 누르면 아래 순서로 처리합니다.

1. 클립보드에 복사한다. 실패하면 "복사했어요"를 띄우지 않고, 결과 글을 선택한 상태로 "직접 복사해 주세요"를 띄운다.
2. 복사 성공 여부와 상관없이 실행 기록을 확정하고, 성공 여부를 `copied`에 남긴다. 끝내겠다는 뜻은 버튼으로 표현했지만 결과를 실제로 썼는지는 모르기 때문에, 복사 실패 실행은 연속 안 고침을 끊는다.
3. 고친 줄이 있으면 S4, 없으면 F-07을 확인한다.

| 항목 | 내용 |
| --- | --- |
| 기록 | `edited`(고침 여부), `passState`(넘긴 방식), 확인할 곳 개수, `elapsedSeconds`(결과가 화면에 표시된 때부터 [복사하고 끝내기]를 누를 때까지 초. 사람이 검토한 시간이 아니다), `copied`(클립보드 복사 성공 여부) |
| 넘긴 방식 | 위에서부터 먼저 걸리는 것으로 정한다. ① `skipped`: 결과가 접힌 상태에서 펼치지 않고 복사했다. 자동 검사에서 확인할 곳이 없었어도 접힌 채 넘겼으면 `skipped`다 ② `nothing_flagged`: 결과가 펼쳐진 상태였고 자동 검사에서 확인할 곳이 없었다 ③ `quick_pass`: 펼쳐진 상태였고 확인할 곳이 있었는데 5초 안에 넘겼다 ④ `stayed`: 펼쳐진 상태였고 확인할 곳이 있었으며 5초 이상 머물렀다. 자동 검사 결과와 사용자가 결과를 펼쳤는지는 다른 정보라 섞지 않는다. 어느 값도 사람이 내용을 검토했다는 뜻이 아니다. `stayed`도 머문 시간만 잰 것이라 화면과 문서에서 "검토함", "검토 완료", "확인함"으로 표현하지 않는다 |
| 복사 뒤 고침 질문 | 복사한 뒤 메일·문서에서 고친 것은 앱이 알 수 없다. 같은 작업을 다시 열 때(결과가 나오기 전, 체험용 작업과 예시 결과 기록은 제외) 마지막 기록이 복사 성공이고 답이 없으면 "지난번 결과를 복사한 뒤 다른 곳에서 더 고치셨나요?"를 [고치지 않았어요]/[더 고쳤어요]/[나중에]로 묻는다. 답은 기록의 `editedAfter`(`yes`/`no`)에 남고, `yes`는 연속 안 고침에 넣지 않으며 이력에는 "복사 뒤 고침"으로 보인다. 답하지 않으면 안 고친 것으로 세되 맡겨볼 만한 때 카드에 "답하지 않은 기록 N개는 안 고친 것으로 셌어요"라고 밝힌다 |
| 고침 판단 | 띄어쓰기·줄바꿈·문장부호를 지우고 비교해 바뀐 줄이 하나라도 있으면 고침. **줄을 삭제한 것도 고침**이다 |
| 빠르게 넘김 | 확인할 곳이 1개 이상인데 `elapsedSeconds`가 `QUICK_PASS_SECONDS = 5`초 미만이면 `quick_pass`. 연속 안 고침을 끊는다 |
| 쓰는 말 | 화면과 문서에서 "안 고침"을 "검토 완료"와 같은 뜻으로 쓰지 않는다. 넘긴 방식은 어느 값이든 사람이 내용을 봤다는 기록이 아니다 |
| 체험용 작업 | 기록은 `mitgo:demo`에만 저장하고 실제 작업 기록과 섞지 않는다 |
| 완료 기준 | 버튼을 누를 때마다 기록이 하나씩 쌓이고 새로고침해도 남는다. 띄어쓰기만 고친 실행은 안 고침, 실제로 글을 바꾼 실행은 고침으로 구분된다 |

### F-07. 맡겨볼 만한 때 판단

| 항목 | 내용 |
| --- | --- |
| 조건 | 마지막 실행부터 거꾸로 센 연속 안 고침 ≥ `HANDOFF_STREAK` |
| 세는 방법 | 최근 실행부터 거꾸로 보며, 셀 수 있는 실행만 1씩 더하고 셀 수 없는 실행을 만나면 멈춘다. 셀 수 있는 실행은 안 고침이면서 `passState`가 `stayed` 또는 `nothing_flagged`이고 `copied: true`인 실행이다. 고친 실행, `quick_pass`, `skipped`, 복사 실패 실행은 건너뛰지 않고 연속을 끊는다. 그래서 셀 수 있는 실행이 실제로 3번 이어져야 제안이 뜬다 |
| 한계 | `nothing_flagged`는 자동 검사에서 확인할 곳을 찾지 못했다는 뜻일 뿐이라, 셀 수 있는 실행이 3번 이어져도 정확하다는 증거가 아니다. S5 주의 문구를 유지한다 |
| 예시 | 최신순으로 안 고침·stayed → 빠르게 넘김 → 안 고침·nothing_flagged → 안 고침·stayed 이면 연속은 1이다 |
| 값 | `HANDOFF_STREAK = 3`. 검증 전 임시 값 |
| 근거 보이기 | S5 카드에 판단의 근거가 된 최근 기록(회차, 앱 안에서 안 고침, 확인할 곳 개수, 머문 초, 복사 뒤 고쳤는지 답)과 확인할 곳 평균 개수를 보인다. 확인할 곳이 한 번도 없었으면 "안전하다는 뜻이 아니에요"를 붙인다 |
| 동작 | 조건을 처음 채우면 S5. S1 카드에 "맡겨볼 만한 때예요" |
| 참고 | 검사 강도를 실적에 따라 조절하는 방식은 ISO 2859-1 샘플링 검사의 전환 규칙을 참고했다. 이 규칙은 연속 10로트 합격 등 조건을 채우면 수월한 검사로 바꾸고, 불합격이 나오면 보통 검사로 되돌린다. 숫자 3은 이 규칙에서 가져온 값이 아니라 엑스포에서 시연할 수 있게 정한 임시 값이다 |
| 완료 기준 | 3번 연속 안 고치고 복사하면 제안이 뜨고, 제안 문구에 정확성 보증 표현이 없다 |

| 항목 | 내용 |

| 완료 기준 | 켠 일은 확인할 곳이 없을 때 결과를 펼치지 않고 복사할 수 있고, 고치면 자동으로 꺼진다 |

## 9. 제출 전 검증

| 항목 | 통과 기준 |
| --- | --- |
| 근거 표시 | 잘못된 자료 번호가 붙어도 신뢰 표시를 주지 않는다. 어떤 줄도 "맞음"류 표시가 없다. 틀린 문장 30줄 테스트 결과가 표로 남아 있다 |
| 숫자 검사 | 자료에 없는 숫자가 든 줄은 항상 "자료에 없음"이다 |
| 규칙 쌓기 | 승인하지 않은 규칙은 다음 실행에 들어가지 않는다 |
| 수정 기록 | 실제로 바꾼 실행과 안 바꾼 실행이 구분되고, 새로고침해도 남는다 |
| 맡겨볼 만한 때 | 3번 연속 안 고침은 제안 조건일 뿐이고, 문구에 정확성 보증이 없다 |
| 확인 생략 | 기본 꺼짐, 고치면 자동으로 꺼진다. 접힌 화면에서 언제든 결과를 펼칠 수 있고 검사 범위가 안내된다 |
| 기록 구분 | 고침 여부와 넘긴 방식이 따로 남는다. `skipped` 실행은 연속 안 고침 횟수에 들어가지 않는다. 화면 어디에도 "검토 완료", "확인함" 같은 표현이 없다 |
| 실패 처리 | API 오류에도 자료가 남고, 예시 결과와 실제 결과가 구별된다 |
| 데이터 안내 | 브라우저 저장과 AI 전송이 나뉘어 안내된다. S0-4 문구가 실제 세 호출(규칙 만들기, 실행, 규칙 후보)에 들어가는 데이터와 맞는다. 익명 기록은 보내지 않는다. 전송 문구가 제출 시점의 Gemini API 무료 이용 조건과 맞는다 |
| 연속 계산 | 빠르게 넘김·확인 생략·복사 실패 실행이 끼면 연속이 끊긴다. F-07 예시 기록에서 연속이 1로 나온다 |
| 겹침 기준 | 결과표가 채워져 있다(2026-10-09). 대안 적용에 따라 화면에 "근거 ①" 대신 "참고한 곳 ①"이 보인다. AI 번호 정확도 확인은 별도로 남아 있다 |
| 연속 계산 코드 | `app/scripts/streak-test.ts` 7개 사례 통과(리뷰 예시 포함, 2026-10-09) |
| 배포 호출 | 배포 주소에서 실제 Gemini 응답이 온다. Vercel 환경 변수에 키가 있다. 한도를 넘기면 `rate_limit`으로 분류된다. 브라우저 코드와 네트워크 응답 어디에도 API 키가 보이지 않는다. 모델명이 문서에 있다는 것과 배포에서 호출이 되는 것은 따로 확인한다 |
| 숫자 통일 | 정의서, PRD, 소개 자료의 설문 숫자가 같은 원본(32명)에서 나온다 |
| 체험 | 처음 온 사람이 30초 안에 확인할 곳 표시를 본다. 체험 기록은 실제 기록과 섞이지 않는다 |
| 배포 | 배포 주소에서 PC 브라우저로 끝까지 쓸 수 있다 |
